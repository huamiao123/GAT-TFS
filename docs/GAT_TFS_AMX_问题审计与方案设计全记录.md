## 1. 记录范围、证据等级与结论边界

### 1.1 这份文档记录什么

本文汇总此前讨论过的模型语义、算子重排、稀疏计算量、AMX 寄存器与数据类型接口、online softmax、数值反例、多头布局、调度、基准测量、研究新颖性等问题，并补充本轮重新检查源码后发现的缺口。每类问题尽量说明：**问题是什么、为什么出现、可以怎样处理、处理的代价是什么、如何验证、当前是否已经解决。**

本文不把此前回答自动视为事实。对已经被反例推翻的方案保留历史记录，同时给出更正；对仓库已有设计与本文补充推导分开标注。用户称原 TFS 为 ICPP 会议版；本次核对的是仓库中文稿和源码，没有独立核验其录用、最终出版或最终提交版本。

### 1.4 当前不研究什么

主线限定为**固定图拓扑上的多头 Vanilla GAT 前向推理**。不默认支持 GATv2、dot-product Graph Transformer、边特征注意力、attention dropout 的训练行为或完整反向传播。它们可以作为未来扩展，但需要重新定义语义与成本。

不研究训练内核，不等于不验证已训练模型的推理精度。最终仍应导入固定 checkpoint，检查层输出、最终预测和任务指标。

## 2. 当前结论与必须更正的前提

### 2.1 方向可以继续，但核心目标要重新表述

建议目标是：

> 在 AMX、AVX 与有界局部缓存之间，以可控精度和最低总执行成本完成多头图注意力，尽量减少全局边中间数组和全局特征中间数组。

不建议将目标写成：

> 所有分数、softmax、聚合和 GeMM 从头到尾都不离开 TMM。

后一表述把一种寄存器驻留方式误当成研究目标。即使它在某些形状上成立，也不代表适合整个模型，更不能忽略数据类型转换、packing 和特征分块。

### 2.2 原 TFS 的真实驻留对象

**[源码]** 原 `amx_tfs_v3.cpp` 在邻居 step 内，将各目标节点当前邻居的特征 gather 到 `Hbuf`，再与 W 执行 AMX 乘加，持续累加输出 C。其核心更接近：

$$
Y_i\leftarrow Y_i+X_jW,\qquad j\in\mathcal N(i).
$$

不是先完整得到 $U_i=\sum_jX_j$，再直接把 FP32 U 当作后一个 BF16 GeMM 的输入。[C03]

仓库中文稿摘要、概览有“Z 保留在 tile”的表述，但方法 3.1、3.2 又具体描述了邻居特征乘 W、**输出 C 的部分和驻留**。这两种描述不能混用。本文按实际运算链解释，不擅自改写原稿实验结果。[C06]

### 2.3 当前 GAT 原型是什么

**[源码]** 当前 `tfs_online_fused` 是：

$$
X(Wa_L),X(Wa_R)\rightarrow\text{分块 online}\rightarrow U_{\mathrm{FP32}}
\rightarrow\text{局部 MKL SGEMM}\rightarrow\text{归一化/ELU/写回}.
$$

它保留线程局部 `16×D` 的普通内存缓冲区，未物化完整全局 U；但**没有执行 TMM 或 BF16 AMX 指令**。[C02]（188–260行）、[C05]

因此，“当前已实现 AMX 上的整链融合”“当前 16×D 缓冲区就是 TMM”均应更正。

### 2.4 当前最重要的负结果

**[仓库记录]** 在第二层 $D=256,K=8,d=32$ 下，匹配 16 worker 和 panel 调度后：

| 路径 | 第二层时间 | 三层 E2E 记录值 |
|---|---:|---:|
| transform-first FP32 控制 | 0.170 s | 0.410 s |
| aggregate-first 局部 U 融合 | 0.297 s | 0.558 s |

这些是共享节点的探索性记录，不是本次 AMX 测试。第二层的更宽稀疏聚合是明确成本；而本轮还发现 E2E 计时边界包含比较等额外工作，因此正式实验应先修复计时。[C05]、第 4.9 节

结论不是“方向失败”，而是：**减少全局 U 并不自动抵消更宽的稀疏运算，必须证明 AMX 与复用的净收益。**

### 2.5 此前表述的修正清单

| 此前容易产生的印象 | 更准确的结论 |
|---|---|
| GAT 的 SDDMM 就是 QK 点积 | 当前是 Vanilla GAT 的加性边打分，可称 generalized/add-SDDMM |
| TFS 原核已经占满全部 8 个 tile | 已核对的 v3 固定使用 7 个 tile |
| BF16 累加 | 目标 `TDPBF16PS` 是 BF16 操作数、FP32 累加 |
| 解决逐行缩放就能直接 U→GeMM | 还存在 FP32→BF16、布局与配置接口 |
| 任意 FP32 有限输入上固定首块原点稳定 | 已被反例推翻 |
| 原测试通过说明方案已经正确 | 只说明有限测试集通过 |
| 多头共用邻居就能共用 attention | 邻接可共享，attention 和 softmax 状态必须独立 |
| head-as-row 可以直接用于两种重排路径 | 原始 X 可共享；投影后的 $Z^h$ 通常不可共享右操作数 |
| rescale 事件减少等于物理搬运减少 | 需要结合完整特征分块和缓冲区生命周期测量 |
| conditional rescale / 整数尺度可以单独算新贡献 | 已有直接相关工作，必须缩小创新性声明 |
| AMX 永远无法从 tile 提取行到 ZMM | 新扩展已有相关接口；只能限定当前目标代际 |

## 3. Vanilla GAT 的数学语义与融合条件

### 3.1 统一符号

| 符号 | 定义 |
|---|---|
| $N,E$ | 节点数、实际参与归约的 CSR 边数 |
| $D$ | 当前层输入特征维度 |
| $K$ | head 数；不与 AMX 的归约维 K 混用 |
| $d$ | 每个 head 的输出维度 |
| $B$ | 一个邻居块的有效/配置边数，具体处分别说明 |
| $R$ | 目标节点调度 panel 大小 |
| $F$ | 特征分块宽度 |
| $X\in\mathbb R^{N\times D}$ | 输入特征 |
| $W^h\in\mathbb R^{D\times d}$ | 第 h 个 head 的权重 |
| $L_i^h,R_j^h$ | 目的/源节点的加性注意力标量 |
| $s_{ij}^h$ | LeakyReLU 后的边分数 |
| $p_{ij}^h$ | 采用某一参考尺度的未归一化权重 |
| $\alpha_{ij}^h$ | 最终归一化注意力 |
| $C,U$ | 根据上下文表示未归一化聚合分子或聚合中间矩阵；必须注明 |
| $\ell$ | 与聚合分子处于相同参考尺度的分母 |

### 3.2 标准执行顺序

对每个 head：

$$
Z^h=XW^h,
\quad L_i^h=Z_i^ha_L^h,
\quad R_j^h=Z_j^ha_R^h,
$$

$$
s_{ij}^h=\operatorname{LeakyReLU}(L_i^h+R_j^h),
\quad \alpha_{ij}^h=\frac{e^{s_{ij}^h}}{\sum_{k\in\mathcal N(i)}e^{s_{ik}^h}},
$$

$$
Y_i^h=\sum_{j\in\mathcal N(i)}\alpha_{ij}^h Z_j^h.
$$

隐藏层随后按模型定义拼接 heads 并施加激活；输出层是否平均、拼接或单头，需要依实现决定。当前仓库是前两层 8×32、最后一层 1×类别数，隐藏层采用 ELU。[R01]、[C01]（61–68、85–86、311–313行）

### 3.3 不先生成完整 Z 的注意力计算

定义：

$$
b_L^h=W^ha_L^h,\qquad b_R^h=W^ha_R^h.
$$

则：

$$
L_i^h=X_i b_L^h,\qquad R_j^h=X_j b_R^h.
$$

这是矩阵乘结合律；可以将用于打分的节点中间特征从 $N\times Kd$ 缩成 $N\times2K$ 个标量。当前 `prepare_attention` 已实现此重排。[C02]（42–65行）

但它只避免了为**打分**先构造完整 Z。选择 transform-first 聚合时，仍然需要某种形式的 Z。$b_L,b_R$ 可随固定模型权重预处理；$L,R$ 依赖当前层 X，每次不同输入/层都要重新生成，不能把动态成本伪装成一次性预处理。

### 3.4 聚合与投影重排

在同一份 $\alpha^h$ 下：

$$
A_{\alpha^h}(XW^h)=(A_{\alpha^h}X)W^h.
$$

若使用未归一化权重 p，则：

$$
U_i^h=\sum_jp_{ij}^hX_j,\qquad
Y_i^h=\frac{U_i^hW^h}{\ell_i^h}
=\left(\frac{U_i^h}{\ell_i^h}\right)W^h.
$$

最后的 GeMM 是**原有 W 的移动**，不是增加一个新线性层。

成立条件必须同时写清：相同边集合、相同每头权重、相同 softmax 分母、线性 W、没有跨越非线性。浮点重排不承诺逐位相同。

### 3.5 不可静默推广的情况

**GATv2。** 注意力中的线性映射与非线性顺序不同，不能一般性地压成两个节点标量。[R02]

**边特征。** 若 score 包含 $e_{ij}$，最大值预扫描、源节点因子缓存等方案要重新推导；可能仍能融合，但不再使用相同简式。

**投影 bias。** 若 $Z_j=X_jW+b$，则归一化聚合在非空行且权重和为 1 时可将 b 移到后面。未归一化分子必须加 $\ell b$，不是直接加 b。注意力中的 bias 也不能随便删除，因为它可能改变 LeakyReLU 分段。空邻域需要单独处理。

**Dropout、残差与激活。** 推理时是否关闭 dropout 必须明确；attention dropout 后的权重不必和为 1。残差投影和 bias 位置按照 checkpoint 对应框架语义保留。不能对各个分块提前做 ELU，然后把结果相加。

**图方向。** 当前是 destination-row CSR。实现允许的是 $j\to i$ 聚合，不可因为数组都叫 row/col 就交换源和目的节点。

### 3.6 “动态”究竟指什么

当前讨论中，图拓扑固定，边权 $\alpha_{ij}^h$ 随输入、层和 head 动态变化。预排序和 CSR 面板结构可复用；边权、节点打分标量和投影特征不能跨不同层或不同输入无条件缓存。

## 4. 当前源码逐项审计：问题、影响与修复办法

本节将**已确认的代码事实、测量问题、健壮性缺口和未来 AMX 风险**分开。没有把所有不足都称为“错误结果 bug”。

### 4.1 C-01：当前 fused 名称容易让人误以为已经是 AMX

**定位。** `gat_tfs_online.cpp` 第 1–5、188–260 行；`Utile/Vtile` 是 `std::vector<float>`，随后调用 `cblas_sgemm`。

**影响。** 能证明的是没有完整全局 U 的 FP32 局部融合，不能证明 TMM 驻留或 AMX 加速。

**解决。** 日志增加 `backend=fp32_mkl`、`amx_instructions=false`、`accumulator_location=thread_local_memory`。未来 AMX 实现使用独立路径名，并核对反汇编。保留当前实现作为语义参考，不能直接改名。

**验收。** 构建产物、运行路径、实际指令和报告一致。[C02]

### 4.2 C-02：aggregate-first 的 D/d 工作量放大是实现选择，不是免费优化

**定位。** `update_raw` 第 80–107 行；fused 第 194–223 行向其传入 D；控制路径第 269–299 行向其传入 d。

**影响。** 第二层逐边逐头处理 256 维而非 32 维，算术工作量增加 8 倍。显式写出 `for (d<D)`，不能由“省去 U”抹掉这一成本。

**解决。** 保留强 transform-first 路径；实现 head-as-row 时测真实跨头复用，不能预设 AMX 峰值足以覆盖差额。必要时按层选择路径。

**验收。** 同时报告 useful FLOPs、executed FLOPs、packing、稀疏访问和端到端时间。[C02]、[C05]

### 4.3 C-03：head 在外层，当前没有发挥 head-as-row 的跨头共享

**定位。** fused 第 198–258 行、控制路径第 276–327 行，head 循环包围 OpenMP 区域。

**影响。** 相同邻居序列和 X 会按 head 多次遍历；相同模型层可能多次建立并行区域。缓存可能产生部分复用，但不能等同于一次加载供 K 个 head 同时计算。

**解决。** 先实现持久 worker 和共享的邻居块生成器，再将所有 head 的 P 放在同一局部块中。不要先改 head 循环再漏掉各自的 $m,\ell,C$。

**验收。** 数值匹配、邻居读取次数、X gather 次数、parallel region 数、缓存失效和尾部时间。[C02]

### 4.4 C-04：`16×D` 是局部内存块，不是可长期全部容纳的 TMM 状态

**定位。** fused 第 194–203 行。

**影响。** 16×256 FP32 为 16 KiB，已经超过 8 KiB TMM 总容量；即便16×128为8KiB，也没有操作数空间。当前代码不受 TMM 限制，不能把它直接翻译成 AMX intrinsics。

**解决。** 明确特征分块、邻居分块、head 分块及 spill 位置。用完整 live-range 表核验，而不是只画局部乘法。

**验收。** 每个阶段最多 8 个物理 tile，所有长期状态都有指定存储位置。[R03]、第6、8节

### 4.5 C-05：热路径存在按行/head 分配状态与统计容器维护

**定位。** `gat_online.cpp` 第 181–185、233–285 行，`OnlineState` 内含 vector，并在每个 row/head 创建；`Stats` 第 74–78 行；TFS 第 19–35、255–256 行。

**影响。** allocator、初始化、`push_back`、统计合并都是实际时间；总统计量还随 $NK$ 增长。它们可以淹没短邻域内核，且不同路径维护统计的形式不完全相同。

**解决。** `CollectStats` 编译期模板或单独构建；生产速度路径只保留必需状态，复用线程局部 workspace；诊断版另行采样。`reserve` 能减少扩容，但不能消除全部写入和汇总。

**验收。** 速度版反汇编/调用统计确认没有逐行分配和行级统计写入；与统计版比较误差，验证统计关闭不改变数学路径。[C01]、[C02]

### 4.6 C-06：`GAT_NO_FINE_TIMING` 不等于关闭所有诊断成本

**定位。** `gat_online.cpp` 第 21–26 行；`build_tfs.sh` 第 8–11 行。

**影响。** 宏把细粒度 `Clock::now` 替换为空时间点，但 `Stats` 的计数、vector、OpenMP critical 合并仍在。命令行 `MODE=speed` 主要跳过 attention 等价性诊断，本身不是编译开关。

**解决。** 明确区分 `profile`、`verify`、`benchmark` 三个入口；`benchmark` 构建和运行时双重确认不做诊断。记录二进制 SHA，避免拿 profile 二进制配 speed 参数就称为纯速度版。

**验收。** benchmark 输出带构建标志；计时区间内没有校验和 printf。[C01]、[C02]、[C08]

### 4.7 C-07：softmax 分段计时包含 rescale，不能再次相加

**定位。** `gat_online.cpp` 第 192–220 行；`gat_tfs_online.cpp` 第 83–100 行。外层 softmax 计时覆盖了内层 rescale 计时区间。

**影响。** `softmax_s + rescale_s` 会双重计数。worker 累计时间与 wall time 虽然都以秒表示，但统计口径不同，不能直接相加或视作互斥分解。

**解决。** 将字段改为 `softmax_inclusive`、`rescale_subtime`，或真正划分互斥计时区间。主图使用互斥阶段；worker-sum 仅用于定位，不能直接占比除以整层 wall time。

**验收。** 校验阶段并集与总时间差异；允许并发和未计时成本，不强行凑成100%。[C01]、[C02]

### 4.8 C-08：`transition=0` 与 `global_u_bytes=0` 不是“无搬运”

**定位。** TFS 的时间结构第 8–10 行；输出第 347–375 行；局部 GeMM 第 232–234 行。

**影响。** transition 没有独立赋值时自然为零；U 的生产/消费访存分别算在聚合和 GeMM 内。`global_u_bytes` 只表示完整全局 U 的逻辑容量，不统计 L/R、局部缓冲区、统计、输出和缓存流量。

**解决。** 未测项目写 `not_measured`，不要用0代替。把“中间数组峰值容量”“逻辑读写字节”“硬件计数器流量”分开。

**验收。** 每个图表标注统计口径，不能用逻辑字节减法充当 DRAM 节省。[C02]、[C05]

### 4.9 C-09：本轮新确认——E2E 计时包含比较、打印和额外拷贝

**定位。** `gat_tfs_online.cpp` 第 455–475 行。

计时从 `e2e_begin` 开始，完成三层后，reference 分支执行 `common=H`；其他分支调用 `compare` 并执行 `acceptable`。随后才计算 `sec(e2e_begin, Clock::now())` 并输出。`compare` 自身会遍历向量并打印。

**影响。** E2E 包含不完全相同的比较或拷贝成本，不是干净的三层推理延迟；与前面 `layer_time_sum` 也不是同一次运行，因为后者来自另一个逐层对照循环。不能据此计算精确的框架开销。

**解决。** 在最后一层计算结束后立即保存结束时间，再执行任何比较、输出或 reference 拷贝。每条路径独立运行与预热；将“冷启动全流程”和“预处理后稳态”分开测。

**验收。** 用人为增加校验开销的实验确认推理计时不变。附录B给出模板。[C02]

### 4.10 C-10：六条路径固定顺序执行、结果同时存活，影响缓存和峰值内存

**定位。** 第 424–453 行先后构造六个 `Result`；第 455–476 行按固定顺序再执行六条完整链。

**影响。** 同一层多个输出与统计容器同时存活；先后路径经历不同缓存、频率和运行库状态。当前 Reference 的 E×K scores/alpha 会暂时增加内存工作集。不能把一次固定顺序实验当成无偏比较。

**解决。** 校验与 benchmark 分离；各候选使用独立进程或随机交错顺序；固定预热方式和输入；确认测量期间不保留其他路径的大结果。单独测量峰值 RSS。

**验收。** AB/BA 次序、独立进程和重复运行的趋势一致；报告分布，而不是挑最快一次。[C01]、[C02]

### 4.11 C-11：本轮新复现——旧 `gat_online` 的失败判定可以漏过 NaN

**定位。** `gat_online.cpp` 第 327–336、348–353 行用 `if(error > threshold) pass=false`。

**原因。** 与 NaN 做 `>` 比较为 false；`std::max(maxe, abs(NaN))` 也可能保留原 maxe，累计平方误差却变为 NaN。两个 `>` 都不成立，旧入口可能打印 PASS。

**本轮实测。** 独立 C++ 复现输出 `old_gt_gate_pass=1`。该程序只复现判定表达式，没有运行完整 GAT。[E03]

**重要区分。** TFS 中 `acceptable` 使用 `<= && <=`，相同 NaN 情况会返回 false，本轮输出 `acceptable_le_gate_pass=0`。不能把旧入口漏洞无差别说成两个入口都必然漏检。

**解决。** 比较前显式检查尺寸与每个元素 `isfinite`；随后计算稳健的绝对/相对误差；阈值由精度契约传入。

**验收。** NaN、±Inf、空输出、全零参考、尺寸不匹配均有单元测试；异常不得以 PASS 结束。[C01]、[C02]（379–385行）

### 4.12 C-12：比较器与输入读取的健壮性不足

**定位。** `load_graph` 第 38–54 行；`compare` 第 290–299 行；TFS `acceptable` 第 379–385 行。

**现有优点。** 已检查文件截断、magic、CSR首尾、rowptr单调与邻居范围。不能忽略已有检查。

**剩余问题。** `acceptable` 没有先检查向量长度；诊断 `compare` 的相对L2分母没有零保护；读取特征没有显式有限性检查；`n*din` 等大小计算及到 `int(n)` 的 MKL 参数转换缺少完整范围保护。图 n 的64位类型与列编号32位类型也需建立契约。

**解决。** 校验乘法溢出与地址空间、文件预期字节、BLAS LP64/ILP64范围、节点编号类型；规定有限输入策略；不使用“内存分配失败自然退出”代替格式校验。

**验收。** 用小型畸形文件做负测试，而不是实际分配超大数组；ASan/UBSan 检查非AMX路径。[C01]、[C02]

### 4.13 C-13：attention 等价性目前主要是打印，不是独立验收门槛

**定位。** `attention_equivalence` 第 387–398 行。

**影响。** 只报告 L/R 的差异，未逐边约束 score、注意力或特别检查 LeakyReLU 分界附近的误差。最终输出可能因抵消而看起来接近，掩盖打分路径的变化。

**解决。** 使用独立小图 oracle，分开比较 L/R、score、分母、加权结果。记录跨零分界、注意力熵、最大概率变化；避免为全图校验重新永久物化所有边数组，可分块抽样/流式比较。

**验收。** 注意力阶段有自己的门槛，不只依赖最终 output 比较。[C02]

### 4.14 C-14：随机参数不等于真实模型的精度验证

**定位。** `make_param` 第 61–68 行；TFS `model` 第 400–402 行。

**影响。** 当前参数由固定种子随机初始化；没有 checkpoint 导入和任务级指标。仓库输出接近只证明该算子实现对当前随机参数一致。

**解决。** 固定一个训练好的 Vanilla GAT，导出参数、激活、head策略和图处理配置；运行真正的逐层与端到端推理。测试集只用于最终验证，误差阈值/路径阈值在开发集上冻结。

**验收。** 权重SHA、框架版本、参考推理、最终节点预测及分类指标均归档。[C01]、[C02]

### 4.15 C-15：数据转换有明确图语义，且当前二进制不是完整任务数据包

**定位。** `prepare_arxiv.py` 第 22–38 行及写出段。[C10]

代码将边双向化、加入自环并去重，按 destination row 存储。这个处理不一定错误，但必须与 reference/checkpoint 的图处理一致，不能说“不作任何处理的官方原图”。标签用于推断类别数；训练/验证/测试划分和任务评估接口需要另行保留和接入。

**解决。** 文件元数据写入方向、去重、自环、节点顺序、源数据hash和转换脚本hash。边特征版本需要定义去重时的合并规则。不要为了去重静默丢弃有意义的多重边。

**验收。** 图变换前后 E、自环数、重复边数、入度/出度分布与节点编号映射可追踪。

### 4.16 C-16：构建和作业脚本依赖硬编码环境

**定位。** `build_tfs.sh`、`run_tfs_arxiv.slurm`。[C08]、[C09]

脚本硬编码工作根、module名称和外部说明文件路径；移到新服务器可能在真正运行前退出。速度二进制仍是 AVX-512/FP32/MKL 的构建，不是 AMX 版。

**解决。** 根路径默认相对脚本解析，允许环境变量覆盖；平台模块加载放入单独配置；研究说明文件可按审计需求记录，但不要使缺少私人绝对路径成为无法构建的原因。AMX 版另列编译参数和权限自检。

**验收。** 在干净 checkout + 文档列出的依赖环境中可构建，不依赖未纳入仓库的私人目录。大图未纳入Git并非缺陷，需提供可复现生成流程。

### 4.17 C-17：度数调度复用了，但不能推导邻域重叠或最佳 AMX 映射

**定位。** `degree_perm` 第 167–175 行；`choose_R` 第 178–186 行。

目前按度数排序，并用 max/avg degree 比值选 R。这对负载调度有依据，但不测源节点重用、邻居并集密度、head数、$D/d$ 或 tile padding。极端单个高度节点还可能支配全图 R。

**解决。** 保留该策略作基线；新增基于度数分位数、面板成本、邻域重叠和工作集的描述量。图静态时预计算，但需报告预处理成本。

**验收。** 选择器必须超过“每层选开发集最快固定配置”的强基线，而不是只超过最差统一配置。[C02]

### 4.18 C-18：原 TFS 的假设不能不经检查搬入 GAT

原 v3 内核是固定维度、静态未加权邻接、BF16特征与权重；其 BF16 转换使用截高位方式，行失活优化依赖度数升序。GAT 的动态 p、不同 D/d/K、尾块和归一化都不是简单改名能够支持的。[C03]、[C04]

**解决。** 明确列出原核前置条件；重新设计加权与非整倍数路径；BF16 转换使用显式舍入契约。若取消度数排序，必须同时检查 `active_from` 一类依赖单调度数的逻辑，不能只删除 sort。

**边界。** 本次没有证明全部历史 TFS 变体存在结果错误；这里只指出移植时必须保持或替换的约束。

### 4.19 C-19：已有公平控制应当保留，但仍可加强

`panel_transform_first_fp32` 已经控制了 panel 和 worker 数，这是正确且重要的实验改进。不能继续拿单线程 `online_avx512` 与16worker融合直接归因加速。

但控制路径仍使用同一 `update_raw` 和大量共同实现，可能共享错误；它也不是完全优化的多线程 AVX 专用核。

**解决。** 一条独立数学/框架 oracle 用于正确性；一条优化后的多线程 transform-first 用于性能。二者职能不同，不能只保留一个“baseline”。[C02]、[C05]

### 4.20 C-20：当前零值和尾部行为必须成为显式接口

旧原型对空行输出0、随后隐藏层ELU仍为0；分数数组最多64，命令行只接受16/32/64，因此当前调用边界相互匹配。不要把内部固定数组直接暴露给任意 block 的新接口。

**解决。** 独立 kernel API 校验 `count≤capacity`，对mask、空行、无效lane、非有限score和非整倍数dim明确定义。AMX填充的无效边须权重0、分母不计入、地址不越界。

**验收。** degree为0、1、31、32、33、63、64、65，以及D/d为15、16、17、31、32、33、40等测试全部覆盖。[C01]、[C02]

## 5. 四类数据流与不能忽略的成本

### 5.1 路径 T：先投影，再融合注意力和低维聚合

$$
Z^h=XW^h,\qquad Y_i^h=\sum_j\alpha_{ij}^h Z_j^h.
$$

稠密投影工作量约为 $2NKDd$，稀疏聚合约为 $2EKd$。全图 Z 的容量为 $NKd$ 个元素，但边分数和归一化权重仍可在线生成，不必物化 $E\times K$ 数组。

**优点。** 稀疏随机访问处理的是 d 维，而不是 D 维；投影是规则 GeMM，适合高效稠密计算。它是必须认真优化的强基线，而不是为了展示融合收益而故意保留的低效实现。

**问题。** 需要生成、写入并读取 Z；若 Z 远大于缓存，产生额外流量。原始 X 在不同头间共享，而 $Z^h$ 不同，因此其多头聚合不能直接沿用 $P_{K\times B}X_{B\times D}$ 的共享右操作数内核。

### 5.2 路径 A：先在线聚合原始 X，再投影

$$
C_i^h=\sum_j p_{ij}^hX_j,\qquad
Y_i^h=\frac{C_i^hW^h}{\ell_i^h}.
$$

稀疏聚合约为 $2EKD$，稠密投影仍约为 $2NKDd$。相对于路径 T，稀疏算术增加比例为：

$$
\frac{D}{d}.
$$

**优点。** 可不保存全图 Z 和全图 U；同一节点的多头可以共享原始邻居 X，形成合法的稠密微块乘法。

**问题。** $D/d$ 大时，算术放大是结构性的；局部 U 仍需要缓冲、归一化、转换和布局衔接。消除全局中间数组不等于消除这些局部开销。

**具体判断。** 当前第二层 $D=256,d=32$，稀疏工作量增加8倍。不能直接把 AMX 的理论峰值与标量循环比较后宣布能够覆盖；应使用包含 gather、padding、packing 的有效吞吐量。

### 5.3 路径 O：沿用原 TFS 的逐边投影展开

$$
Y_i^h=\sum_j\alpha_{ij}^h(X_jW^h).
$$

它可以让较窄的输出部分和驻留，但如果不复用源节点投影，工作量的主项达到 $2EKDd$。同一 $X_jW^h$ 可能因源节点被不同目的节点访问而重复计算。[C03]

**适用可能性。** 特殊小维度、非常低度图、输出部分和的驻留收益足以抵消重算，或者能有效缓存源节点投影。都需要实验，而不是只凭分配律。

**不应再使用的表述。** “原 TFS 消除 AH 后没有额外计算，因此 GAT 也可以无代价移动 W。”实际执行顺序与算术成本必须同时列出。

### 5.4 路径 P：源节点面板的局部投影缓存

对一组目标节点所需的源节点集合 $S_p$，只生成局部 $Z_{S_p}$，随后在面板中复用。这样可以兼顾低维稀疏聚合与不保存全图 Z，但不同面板可能反复投影同一源节点。交接文档已经提出该方向。[C07]

定义：

$$
\gamma=\frac{\sum_p|S_p|}{|\bigcup_pS_p|}.
$$

这是面板间源节点投影的重复率，不包含 head 的重复计数。必须同时报告缓存容量、替换策略、不同面板是否并发和源节点工作集大小。

**修复思路。** 将局部缓存视为显式算法对象：key 至少包括源节点、层/输入版本、head、权重版本和精度格式。不能仅用节点 ID 缓存后跨层复用，因为每层输入已改变。

### 5.5 打分预处理也不免费

在 aggregate-first 重写中，形成两组 $b=Wa$ 的成本约为 $4KDd$，再计算所有节点的左右标量约为 $4NKD$。固定权重推理时，b 可预计算；L/R 依赖当前层输入，不能跨不同输入直接复用。

在 transform-first 中，已有 Z 后计算 L/R 约为 $4NKd$。比较时要避免将这些成本遗漏或重复计入。当前 `prepare_attention` 和 `pack_head_weight` 每次调用都会执行，正式实验应清楚地区分首次准备与稳态调用。[C02]

### 5.6 不能消除的输出与尚未消除的数组

即使不物化边分数、alpha 和全局 U，完整层通常仍有：输入 X、CSR、层输出、L/R 标量、权重和线程局部工作区。输出 $N\times Kd$ 是层接口的一部分，不应为了叙事将其称为“已全部消除的中间特征”。

还要区分三种量：

1. **峰值容量**：某时刻实际同时存活多少字节。
2. **逻辑访问量**：按算法计算的读写次数乘以数据大小。
3. **实际硬件流量**：L1/L2/LLC/内存控制器观测到的流量。

这三者不能互相替代。局部 buffer 仍在内存地址空间中；它是否命中某级缓存必须测量。

## 6. AMX 的硬约束及完整寄存器设计

### 6.1 BF16 乘法与 FP32 累加的接口边界

当前目标上的 `TDPBF16PS` 读取 BF16 操作数并累加到 FP32 destination。[R03]、[R04]

由此得到两个不同的问题：

| 操作 | 需要的典型接口 | 是否一定需要 BF16 转换 |
|---|---|---|
| 给 FP32 accumulator 的各行乘缩放因子 | TMM store → AVX FP32缩放 → TMM load | 否 |
| 将聚合 FP32结果作为下一次 BF16 GeMM 输入 | store → 归一化/转换/packing → load | 是，除非更换后端或精度策略 |

“每次 rescale 都要转成 BF16”是不必要的额外损失；“后续 GeMM 不需要转换”则忽视了数据类型契约。

### 6.2 寄存器数量、形状与逻辑容量都要满足

目标 palette 提供8个 tile，每个最多16行、每行64字节。[R03]

当前代码的软件 U：

$$16\times256\times4=16\text{ KiB}.$$

仅容量就超过全部 TMM 的最大总容量。改成8个 head为行后：

$$8\times256\times4=8\text{ KiB},$$

虽然等于最大总容量，但仍没有操作数空间；而且采用每个结果tile为 $8\times16$ FP32 的映射，需要16个结果tile，**寄存器个数会先超限**。

容量计算与具体矩阵形状计算都必须做，不能只看其中一个。

### 6.3 可实现的局部微核草案

对一个节点、8个 head、32个邻居、64维特征块：

$$P_{8\times32}\,X_{32\times64}\rightarrow C_{8\times64}.$$

候选配置：

| Tile | 内容 | 说明 |
|---|---|---|
| T0–T3 | 四个 $8\times16$ FP32输出块 | 共2KiB有效结果 |
| T4 | $8\times32$ BF16权重P | 8行，每行64字节 |
| T5、T6 | 当前/后续源特征子块 | BF16点积要求的右操作数布局 |
| T7 | 空闲或专用扩展 | 不预先假定一定可用于双缓冲所有状态 |

这是**寄存器草案**。双缓冲是否有效、装载能否重叠以及8行利用率，都要通过微基准核验。标量最大值、分母和尺度版本不占用 TMM，可放在通用寄存器、ZMM或局部状态中。

### 6.4 右操作数 packing 是实质工作

不能将普通行主序 $X_{B\times F}$ 直接当作右操作数 tile 的正确布局。对 BF16 成对乘加，可用如下逻辑描述打包：

$$
B_{pack}[k_{pair},2f+\lambda]
=X[2k_{pair}+\lambda,f],\quad\lambda\in\{0,1\}.
$$

实际指令还要求匹配配置字节数、K维长度和尾部填充。动态邻居 X 需要 gather 与相邻归约元素交织；与原 TFS 可静态预打包 W 的情况不同。

**解决思路。** 将 gather、FP32→BF16、成对交织尽量组合为一次处理；统计有效输入字节、packing写入、tile load分别是多少。只在预打包输入上测 AMX，不能作为端到端聚合性能。

### 6.5 整层循环的三个选择

**邻居块优先。** 生成一次P，依次消费多个特征块。优点是分数/指数不重复；缺点是不能驻留的结果块需要读写局部缓冲区。

**特征块优先。** 一个结果块跨完整邻域驻留。优点是减少该结果块往返；缺点是重遍CSR、重生成权重，或保存权重数组。

**混合驻留。** 保留部分结果块，其他块使用局部缓冲。优点是能连续调节资源；缺点是实现和尺度元数据更复杂。

**不能同时默认：** 单次扫描邻居、所有D维结果驻留、不保存边权重、且无需额外重算。在当前配置下，需要明确牺牲哪一项。

### 6.6 accumulator 的基础搬运可能大于 rescale 额外搬运

若每个邻居块都读写完整 $K\times D$ FP32状态，渐近读写约为：

$$
8KD\ \text{字节/邻居块},\qquad \frac{8KD}{B}\ \text{字节/边}.
$$

$K=8,D=256,B=32$ 时约为512字节/边。首块初始化、末块消费、保留部分结果块会改变这个数；这里是特定循环组织的量级估算，不是测得的DRAM流量。

**核心问题。** 即使消除全部额外 rescale，基础特征分块搬运仍可能存在。因此应将 `base_accumulator_bytes` 与 `extra_rescale_bytes` 分开统计。

### 6.7 Tile 配置不是可以随意切换的普通参数

Intel 文档明确：成功执行 `LDTILECFG` 会初始化/清零 TILEDATA。[R03]

由此得到三条工程约束：

- accumulator仍驻留时，不可为了尾块K尺寸直接重新配置并继续沿用旧结果。
- 调用使用AMX的库函数或另一种微核前，必须明确谁拥有tile配置与结果生命周期；不能依赖被调用方自动保存。
- 改变聚合/GeMM配置要以“已提交所有活跃tile”为边界，配置次数与开销计入基准。

### 6.8 为什么“用对角矩阵做逐行缩放”暂不作为主方案

形式上 $C'=\operatorname{diag}(r)C$。但在目标 AMX-BF16 上，C原本是FP32 accumulator，作为右操作数仍须转换、重新布局；还引入对角矩阵的大量零乘法和额外tile。

它并没有消除最关键的类型边界，而且可能提前量化C。除非新硬件指令或特定量化容错提供明确收益，否则只适合对照实验，不应作为“无搬运缩放”的解决答案。

### 6.9 必须限定硬件代际

新一代 AMX-AVX512 接口已提供 tile 行到向量及相关转换能力；这不等于当前 Xeon Max 平台可直接使用，也不等于自动具备任意FP32 tile逐行原位乘法。[R06]、[R07]

论文应写清：目标ISA、实际支持的指令、依然存在的数据依赖和精度接口。若方法只利用旧ISA的某个缺口，应讨论新ISA下价值是否仍存在。

## 7. online softmax：全部候选方案、推导与失败条件

### 7.1 正确的状态不变量

对一个节点、一个 head、已处理边集合 $E_t$，允许选任意统一参考值 c：

$$
C_t=\sum_{j\in E_t}e^{s_j-c_t}V_j,\qquad
\ell_t=\sum_{j\in E_t}e^{s_j-c_t}.
$$

最终 $Y=C_t/\ell_t$。若参考从 $c_t$ 改成 $c_{t+1}$，旧分子与旧分母必须同时乘：

$$r=e^{c_t-c_{t+1}}.$$

这是所有延迟、合并、分段方案必须保持的不变量。所谓“在线”是分块消费并维护有界摘要，不要求参考值在每个块都恰好等于最大值。[R08]、[R09]

### 7.2 S0：标准分块 online，必须保留的正确性/性能基线

$$
m'=\max(m,\max s_b),\quad r=e^{m-m'},\quad p_b=e^{s_b-m'},
$$

$$
C'=rC+p_bV_b,\qquad\ell'=r\ell+\sum p_b.
$$

首块没有历史结果，应直接初始化，不需要对无意义的 $-\infty$ 差进行普通运算。空行必须由API单独定义。

**作用。** 作为稳定、简单、容易独立核对的基线；不因为存在可优化的rescale就删除它。

**局限。** 每次running maximum升高都可能触发旧C缩放；硬件代价取决于当时C在哪里以及多少行共享tile。

### 7.3 S1：最终归一化延后——保留，但不是新贡献

持续累加未归一化分子C，结束时再除以分母，而不是每个块将结果重新归一化。这是已有online/FlashAttention技术的一部分。[R08]、[R09]

对于aggregate-first，还可选：

$$Y=(C/\ell)W=(CW)/\ell.$$

前者可以把归一化合并进FP32→BF16及packing；后者可以在较窄的输出d维执行除法。两者在浮点和转换位置上不同，需同时比较误差。

**禁止误解。** 延迟除法不等于允许忽略历史C的尺度变化。例子 $s=[0,\ln2],V=[1,0]$ 的正确输出是1/3；分母更新而旧C不缩放，会错误得到2/3。

### 7.4 S2：精确最大值预扫描——不是 online 主线的替代，而是强对照

Vanilla GAT 的 LeakyReLU 单调，故：

$$
m_i^h=\operatorname{LeakyReLU}\left(L_i^h+\max_{j\in\mathcal N(i)}R_j^h\right).
$$

第一遍只读CSR邻居和R标量，求最终参考值；第二遍才计算指数与完整特征聚合。无需保存边分数，不需要第一遍读取全部D维特征。[C07]、[R01]

**收益来源。** 以一次轻量标量扫描换掉running-max重缩放。

**代价。** CSR与R访问多一遍，可能增加随机标量读取、缓存扰动和短行开销。若存在边特征或GATv2，该简化不一定成立。

**应比较的不是：** 一遍算法与“所有特征读取两遍”的人为弱基线，而是与这个精确的标量预扫描对照。

### 7.5 S3：有界窗口的条件重定标

把真实观测最大值m与参考c分开。设窗口宽度 $\tau=w\ln2$，当：

$$\max s_b\le c+\tau$$

时，继续用c生成 $p_b=e^{s_b-c}$，不缩放旧C。只有越过窗口才选择新参考值并重定标。

允许 $p>1$，因为它是未归一化权重。在窗口内 $p\le2^w$。若该行有n条边且 $|V_{j,k}|\le B_V$，则：

$$\ell\le n2^w,\qquad |C_k|\le n2^wB_V.$$

这些范围界可用于排除明显溢出，但**不能**保证分数差的精度、相消后的相对误差或次正规数行为。

**实现易错点。** 越界比较必须相对当前参考c，不是仅比较相邻两个块最大值的增量。每次只增长一点的慢斜坡会累积成大漂移。

**最坏情况。** 每个新块都大幅提高最大值，仍然每块重定标。不能承诺减少固定比例。

**创新性边界。** FlashAttention-4 第3.1.4节已有条件缩放和组内合并触发的直接相关机制。[R10]

### 7.6 S4：固定首块原点的整数二进制参考——保留历史，但不能无条件继续使用

上一轮候选令首块原点为a：

$$x_j=(s_j-a)\log_2e,\quad p_j=2^{x_j-q},$$

q为整数。越过窗口后 $q'=\lceil\max x_b\rceil$，历史结果乘 $2^{q-q'}$。

**实数性质。** 统一参考尺度改变不会改变softmax；二次幂缩放在正常可表示范围内有良好舍入性质。这里限制的是参考尺度，不是将所有分数或权重限制为整数/二次幂。

**已确认漏洞。** FP32先计算 $s-a$ 可能丢掉后续分数差。$s=[-10^8,-10^8,0,1]$ 时，后两个差值均可舍入成相同的 $10^8$，后续再减q无法恢复。旧实现输出0.5而非0.73105858。[E02]

**其他边界。** q的整型范围、转换回浮点的精度、指数缩放因子先下溢、FTZ规则都必须检查。不能只检查结果是否finite。

**状态。** 旧版本仅作为反例和对照，不能标记为已解决的通用数值方案。整数尺度相关思想已有文献，不能单独宣称首次。[R11]

### 7.7 S5：可重置参考的修复基线——本轮已做软件验证，尚非高性能实现

最直接的正确性基线：

1. 分数仍采用输入FP32值，但参考c与差值运算用FP64。
2. 首块将c设为实际块最大值。
3. 当 $\max s_b-c>\tau$，直接将c重置为新的实际最大值，不继续相对无限远的旧原点计算。
4. 旧C、旧分母重缩放时，先用高精度因子与旧值相乘，再舍入回FP32，避免因子先变成0。
5. 权重与存储的C/分母仍是FP32，检查非有限值与分母有效性。

**[本轮实测]** 该基线修复了 $10^5$ 至 $10^9$ 五个固定原点反例，并通过原八组合成测试；但它不提供任意输入下的完整FP32误差保证，也不是AMX/SVML实现。[E03]

**后续优化候选。** 在有限窗口内保留整数q，窗口外动态换原点a；尺度版本记录完整 $(a,q)$。跨原点的缩放一般不再是纯二次幂，应承认并实现这一代价。另一候选是保留补偿参考表示，但要分别验证运算精度与指令开销。

**不能偷换。** 用FP64修复的参考程序只是验证基准。若最终高性能版改回FP32差值/近似exp，必须重新跑全部反例。

### 7.8 S6：多个 head 合并提交，但每个 head 保持独立尺度

当任意head越界导致一次物理提交时，可同时检查其他head的进度，将其参考提前移到各自当前最大值，减少紧接着发生的第二次搬运。

这里共用的是“提交时刻”，不是一个公共c。采用自然对数参考时，可令 $c_h′=\max(c_h,m_h)$，只向前推进；二进制方案也应保持参考不后退。公共参考会使不同分数幅度的head互相影响数值范围。

**收益判断。** 同时统计逻辑越界数、被提前重定标的head数、实际tile搬出次数和字节。逻辑缩放变多而物理提交变少，可能仍然有利；反之也可能更慢。

**边界。** 已有warp级any-trigger的相关设计，AMX版的新内容应体现在物理tile、异步head状态和分块缓冲区的协同，而不是合并触发的概念本身。[R10]

### 7.9 S7：将必要缩放合并到已有的装载、存储和转换

对每个存储的特征块记录旧参考 $c_{stored}$。下一次读取时，若当前逻辑参考为 $c_{current}$，先按：

$$C_{aligned}=e^{c_{stored}-c_{current}}C_{stored}$$

对齐，再累加当前P对应的结果。若原本就要把C写回局部缓冲，可在这个边界更新；最终还可与归一化/类型转换合并。

**实际能消除的东西。** 一次专门为rescale制造的TMM store/load。

**仍然存在的东西。** 读取/写入局部数据、AVX乘法、版本检查、必要时的尺度对齐。不能把“附带完成”写成“零成本”。

**关键未完成项。** 各个C块、P块和分母的版本协议，见第8节。

### 7.10 S8：分段结束、先投影、再在低维空间合并

每段保存：

$$C_s=\sum_{j\in E_s}e^{s_j-c_s}X_j,\quad\ell_s=\sum_{j\in E_s}e^{s_j-c_s},\quad Z_s=C_sW.$$

最终或逐段合并：

$$
M=\max_s c_s,\quad
Y=\frac{\sum_s e^{c_s-M}Z_s}{\sum_s e^{c_s-M}\ell_s}.
$$

**好处。** 将重缩放/合并状态宽度由D降到d；每段内部保持参考，不修改已有tile。

**代价。** 每段都要投影。段数S时，投影主项可能从 $2NKDd$ 增为与 $\sum_iS_i$ 成正比。不能只记录缩放变少而漏掉多次GeMM。

**实施限制。** 不保留无限多段，应维护有界摘要并及时合并。不同段的归一化输出不能不加权地平均，必须保留参考与分母。激活函数放在合并之后。

**候选触发。** 只在参考真正越界或资源阈值达到时结束段，不是每32条边都无条件投影。用测得的“额外投影成本 vs 节省D维搬运”决定采用条件。[C07]

### 7.11 S9：固定全局上界、预测最大值或永久冻结——只能带数值证据使用

给每行一个保证高于所有分数的参考，理论上不需要重缩放；但参考过大可令整行指数下溢，分母为0。使用经验估计或冻结最大值也要证明偏移范围及误差控制。

VFA等工作已讨论初始化、遍历重排与冻结相关技术，不能忽略其前提或直接迁移结论到CSR Vanilla GAT。[R12]

**本项目建议。** 保留为后续研究，不作为第一版默认。优先实现精确预扫描和有界单遍方案。

### 7.12 S10：根据分数排序以减少最大值更新——收益与多头共享可能冲突

若邻居按R降序，Vanilla GAT每个head的最大值可在早期出现。但R依赖当前输入、层和head；不同head一般需要不同顺序。

排序成本、动态图值、不同头顺序破坏共享X读取、以及数据结构重建都必须计入。静态degree排序不能替代动态score排序。

**候选。** 仅对超长行做低成本分桶或使用已有局部顺序；不要在未经验证时引入全图每层每head排序。

### 7.13 online 方案的优先顺序

先完成S0标准实现与S2精确两遍对照；S5作为修复后的软件数值基线；再将S3、S6、S7接入真实AMX数据流。S8单独实施对照，避免多个机制叠加后无法归因。S4旧实现保留作反例，S9/S10暂不进入主路径。

**判定原则。** online主线值得继续，不代表必须坚持某一种参考表示。能够维持正确的不变量、减少总成本、并适配实际资源的方案才应保留。

## 8. 分块、延迟缩放和多头流水线的状态协议

### 8.1 为什么仅有三个标量和一个数组的NumPy程序不够

软件验证通常同时更新完整C。真实内核可能同时有：TMM中的一个特征块、旧尺度的局部C块、已生成但未消费完的P块，以及已推进到新尺度的分母。任何一份数据的尺度错配，都可能产生有限但错误的结果。

因此，下一阶段应先实现一个**分块状态模拟器**，再把相同协议搬到intrinsics。模拟器必须刻意乱序安排装载、延迟缩放和双缓冲，不能只测试同步更新完整数组。

### 8.2 每份状态至少记录哪些元数据

| 对象 | 必须明确的身份与版本 |
|---|---|
| 节点/head状态 | node、head、输入/层版本、参考表示、已处理边前缀、分母 |
| C特征块 | node/head、feature范围、它自己的参考版本、已累加边前缀、驻留位置、dirty标记 |
| P邻居块 | node、head范围、邻居范围、参考版本、格式/精度、剩余消费者数 |
| 局部投影面板 | 层/权重版本、node顺序、head、归一化完成状态、输入布局 |
| TMM配置 | 当前所有者、配置ID、各tile的用途、是否存在尚未提交结果 |

参考表示可以先用一个FP64 c；若采用二进制局部尺度，则元数据是完整 $(a,q)$ 或其无歧义的等价值，不能只留下q。

### 8.3 必须始终满足的五个不变量

**I1：尺度一致。** 一个C块在自己的参考 $c_f$ 下表示已处理边的加权和。加载到新参考c时必须乘 $e^{c_f-c}$。

**I2：边覆盖一致。** 最终归一化前，所有特征块必须覆盖相同的邻居前缀，且每条有效边恰好处理一次。不能把一个较旧C块除以已经包含未来边的最终分母后直接输出。

**I3：分母只更新一次。** 每个邻居块、每个head更新一次分母，不随特征分块数量重复。

**I4：P的含义不可变。** P生成后直到所有消费者完成，其参考版本和内容保持不变。下一块P不能覆盖尚在消费的缓冲区。

**I5：配置改变前提交。** 调用可能改变TMM配置的代码前，所有需保留结果均已写入正确版本的缓冲区。

### 8.4 邻居块优先的一种可验证执行协议

```text
begin row/head-group:
    初始化空状态、C块版本和分母
for each neighbor block b:
    读取边索引与L/R，生成块分数
    决定是否需要新参考；冻结本块参考 ref_b
    对分母历史部分进行一次必要尺度对齐
    生成不可变 P_b，记录 ref_b、边范围、consumer_count
    分母加入 sum(P_b)，仅一次
    for each feature block f:
        读取 C_f 及其旧参考版本
        对齐 C_f 到 ref_b（允许合并进已有load处理）
        gather/pack X_b,f
        执行 C_f += P_b * X_b,f
        提交 C_f 或登记其仍驻留TMM
        更新 C_f 的边前缀与参考版本
        consumer_count -= 1
    assert P_b.consumer_count == 0
    发布本块完成状态，允许复用P缓冲
finalize:
    检查所有C块边前缀一致
    对齐到可用于最终归一化的参考
    归一化、精度转换、投影、激活及按原node顺序写回
```

这份协议先牺牲部分异步性换取明确正确性。后续双缓冲优化只能改变准备/消费时刻，不能破坏上述依赖。

### 8.5 延迟缩放不是删除缩放，而是推迟物理执行

逻辑参考可以先变更，而每个C块带自己的旧参考。只要消费时准确对齐，代数仍成立。

但出现以下情况时不能只改元数据：

- 旧值已经因提前量化或错误缩放下溢为0。
- 某块同时混入了两种参考的贡献，却只记录一个版本。
- 旧尺度因子已被低精度计算成0，之后试图恢复大数的有效贡献。
- P已经在旧尺度生成，消费者却将其解释为新尺度。

这些是不可逆错误，不是补一个最终除法能够恢复的。

### 8.6 回退要定义“从哪里恢复”

若发现当前行不满足窗口/指数范围或非有限检查，应明确：重放当前行、重放当前段，还是采用保留的高精度摘要。仅切换后续块到FP64不足以修复前面已丢失的信息。

建议第一版的安全回退是**从当前行起点重新计算独立参考路径**，便于验证。记录回退行数、边数和总时间。之后再研究分段检查点，以减少重算。

### 8.7 如何测试状态协议

对同一张微图，枚举或随机化：特征块顺序、P双缓冲覆盖时机、head越界时刻、延迟读取次数、分母更新时间、段合并树。每步都可将所有块转换到统一参考，与FP64前缀oracle比较。

应加入故意破坏协议的负测试，例如将P参考版本改错一代、分母重复更新、跳过一个特征块的缩放；测试程序必须检测失败，不能只是始终输出PASS。

## 9. 精度问题、反例、修复候选与误差预算

### 9.1 精度路径需要拆成独立变量

至少区分：

1. X、W、a 的存储精度；
2. $X(Wa)$ 与 $(XW)a$ 的执行顺序；
3. L/R及边分数的计算精度；
4. 指数实现与参考尺度计算；
5. P进入AMX前的量化；
6. 加权聚合的累加顺序；
7. U进入后一个GeMM前的转换；
8. 分母、最终归一化和激活。

将这些全部同时改成“混合精度”后只测一个最终误差，不利于定位原因，也无法形成可信的精度合同。

### 9.2 反例一：固定原点使当前分数差异消失

$$s=[-10^8,-10^8,0,1],\quad V=[0,0,0,1]^T.$$

正确值：

$$Y=\frac{e}{1+e}\approx0.73105858.$$

旧候选先计算 $(s-a)$，a为首块的 $-10^8$，两个后续值0和1在FP32大数差中失去区分，输出0.5。标准FP32 online输出约0.73105860。[E02]

**原因。** 这是参考坐标计算精度，不是exp溢出。finite检查不能发现。

**解决候选。** 可重置原点、高精度参考差、补偿表示，以及明确的输入范围与回退；第7.7节的FP64参考基线已修复该测试，但优化实现待完成。

### 9.3 反例二：缩放因子先下溢，乘积本来却可表示

本轮新增测试：

$$s=[0,120],\quad V=[10^{38},0]^T.$$

正确输出约 $7.67\times10^{-15}$。普通FP32流程先计算 $e^{-120}$，该因子可能舍入为0，再乘旧C，丢掉本来正常可表示的乘积。

**[本轮实测]** 普通测试程序输出0；用FP64计算缩放乘积后再存回FP32的候选输出约 $7.6676480\times10^{-15}$。[E03]

**解决思路。** 指数分解缩放、`scalbn`类语义或高精度乘积，而不是先把缩放因子低精度化。二次幂因子也有同样问题：因子独立不可表示，不代表因子与C的乘积不可表示。

**边界。** 此例的绝对输出很小，不代表已观测到真实任务失败；它用于完善数学和数值合同。

### 9.4 反例三：新增 U 的 BF16 转换破坏线性重排的实际精度

$$
A=[0.5,0.5],\quad
X=\begin{bmatrix}1&1\\1.0078125&1\end{bmatrix},\quad
W=\begin{bmatrix}1\\-1\end{bmatrix}.
$$

X与W的元素均可被BF16精确表示。先投影再聚合：

$$A(XW)=0.00390625.$$

先聚合：

$$U=AX=[1.00390625,1].$$

舍入成BF16得到 $[1,1]$，再乘W得到0。[E02]

**意义。** 错误并非输入X/W量化导致，也不是注意力或分母算错，而是额外的U转换位置使有意义的小差被抹掉。不能仅凭实数结合律宣称两条BF16实现等价。

### 9.5 U 精度的三个修复候选

**Q1：U后的投影保留FP32。** 聚合可按受控精度加速，后续用FP32后端；避免该转换，但可能损失GeMM加速。是必须保留的精度对照。

**Q2：高低两部分补偿。**

$$U_{hi}=\operatorname{BF16}(U),\quad U_{lo}=\operatorname{BF16}(U-U_{hi}),$$

$$UW\approx U_{hi}W_{BF16}+U_{lo}W_{BF16}.$$

**[本轮实测]** 上述反例中，$U_{lo}=[0.00390625,0]$，两部分结果恢复0.00390625。[E03]

这只说明修复了该反例，不代表任意FP32 U都被精确表示。代价约为额外一次同形状GeMM和转换/累加。W本身的量化误差仍存在；若W也拆两部分，会增加更多交叉乘积，不能忽略。

**Q3：接受经过验证的误差并进行形状/层级选择。** 对误差敏感层使用FP32或补偿路径，其余层使用单BF16。精度选择须基于开发验证，不可通过测试集挑结果；配置选择成本与回退比例要报告。

### 9.6 分子和分母应采用相容的实际权重

若AMX使用 $\widehat p=\operatorname{BF16}(p)$，分母却使用原p：

$$\widehat Y=\frac{\sum\widehat p_j\widehat V_j}{\sum p_j},$$

即使V恒定，输出也会出现额外尺度偏差。

候选是：

$$\widehat\ell=\sum\operatorname{FP32}(\widehat p_j),\qquad
\widehat Y=\frac{\sum\widehat p_j\widehat V_j}{\widehat\ell}.$$

应与实际硬件对BF16次正规输入的处理一致，而不是仅按软件内存中非零的位模式累加。AMX相关次正规数规则见Intel文档。[R03]

**局限。** 相同量化权重不意味着分母和分子的归约顺序完全相同，因此常量测试应使用误差阈值；它也不能修复U转换和有符号相消。

### 9.7 为什么相对误差不能单独作为准则

分量 $y=\sum_jp_jv_j$ 若因正负相消接近0，条件数：

$$\kappa=\frac{\sum_j|p_jv_j|}{|\sum_jp_jv_j|}$$

可能很大。此时极小绝对扰动也会产生很大相对误差。

因此同时报告max-abs、RMS、带下限的relative-L2、误差分位数、符号/分类变化和任务指标；明确接近零的参考如何处理。不能只调整容差让某个结果通过。

### 9.8 指数近似、FTZ与输入合同

向量exp通常由软件库或编译器向量数学实现，不是“一条AVX硬件exp指令”。当前 `_mm512_exp_ps` 依赖工具链支持，应记录编译器和相关数学库。[C01]

FP64软件测试没有完整覆盖AMX的加法顺序、舍入和次正规数归零。最终验收至少包括实际BF16字节输入、实际AMX输出、FP32控制与高精度参考。

非有限X/W/score要明确定义拒绝或处理规则。对有限但范围过大的输入，必须给出可验证的回退条件。不要将“通常不会发生”写成正确性依据。

### 9.9 多层累计与真实 checkpoint

当前随机参数能够检验部分数值一致性，但不能验证训练模型的敏感性。[C01]、[C02]

推荐按层定位误差：使用共同FP32输入比较每层；再让各路径独立传递自己的前层输出，检验累计误差。两种测试回答不同问题，都需要保留。最终用固定checkpoint和固定评估集合比较预测与任务指标，不需要实现反向传播。

## 10. 多头映射、布局衔接、短行与超长行

### 10.1 为什么16个目的节点的第k个邻居不能共享归约坐标

矩阵乘 $P_{16\times B}X_{B\times D}$ 要求P的第k列与X的第k行对应同一个源节点。但不同目的节点的第k个邻居通常不是同一节点。

合法处理是使用源节点并集、共享源节点块、块稀疏结构，或采用不同映射。若16行邻域完全不重叠、每行B条边，源并集为16B，P的密度为1/16，许多乘法处理零。

定义局部有效密度：

$$\rho_p=\frac{E_{\mathrm{valid},p}}{R_p|S_p|}.$$

它与按degree排序降低尾部空转是不同指标。需要分别报告行长度利用率和邻域共享密度。

### 10.2 Head-as-row 的机会与边界

同一节点的不同head共享邻居，因此：

$$C_i=P_iX_{\mathcal N(i)}$$

有合法共同归约轴。优势来自共享原始X读取与规则矩阵乘，不是共享softmax状态。

边界有三条：

- head少于16时不能按满16行峰值估算；最后一层只有1个head，收益结构不同。
- D大时完整C无法驻留，见第6节。
- 后续不同head使用不同 $W^h$，不能用一个统一右操作数完成所有head的投影。

### 10.3 从 head-major 聚合衔接 node-major GeMM

在R个目的节点的局部面板中，使用 $U[h][n][f]$ 布局。单节点聚合后，tile的第h行直接写入对应head、该节点的特征范围。行stride可设为 $RD\cdot4$ 字节。[R04]

该布局使每个 $U[h]$ 成为 $R\times D$ 矩阵。随后归一化、BF16转换和W乘法可按head执行。

**候选A。** 使用带stride的tile store，减少独立转置。

**候选B。** 连续存储聚合结果，在归一化＋转换＋packing时一并转置。

A可能增加跨页步长和缓存不友好的写入；B增加一次整理但更连续。必须实测，不能只看“少了一次转置”的逻辑描述。

### 10.4 为什么把两个节点堆到16行不一定免费

若每个节点8个head，合并两个节点看似填满16行。但两节点邻居不同，共享右操作数需要源并集或块对角权重，可能增加零乘法和gather。

只有当邻域足够重叠或两个较小块的额外工作低于满行收益时，才值得采用。应将其作为带密度参数的候选，而不是默认填满tile的方法。

### 10.5 短行与尾块

degree为3时，固定B=32会有大量无效位置。备选包括AVX短行核、较小固定tile配置、同邻域/高重叠节点分组，以及固定配置安全padding。

无效边必须满足：权重0、不贡献分母、不触发max、无越界访存。不能先对非法索引gather后再用mask乘0。

改变tile配置前必须保存活跃结果。不要把 $B=31$ 的尾块简单理解成只改一个参数而无其他影响。[R03]

### 10.6 单头输出层与任意维度

当前层配置是 $8,8,1$ 个head，最后一层输出40维，均应纳入第一轮实际实现，而不是只展示最整齐的8head/32维。[C02]

对 $d=40$，尾部输出列需要安全处理；不能把40强制四舍五入成32。对一般K不是8/16、D不是32倍数，明确padding成本与有效输出范围。

### 10.7 超长行分段并行

将同一邻域划分为多个工作段，各段产生 $(c_s,\ell_s,C_s)$ 或投影后的 $(c_s,\ell_s,Z_s)$，按第7.10节公式归约。

**必须处理。** 工作分配、部分结果容量、归约顺序、跨线程尺度对齐、deterministic模式，以及避免同一行多个worker写同一输出。

不能对已经归一化的段输出做普通平均；不同段分母可能相差很大。也不能让段数随度数无界增长而不计临时内存。

### 10.8 度数倾斜仍然重要，但不是唯一论文主张

用户希望不把“处理度数倾斜”作为主要创新，这并不意味着可以忽略它。它是保证整体实现可用的工程约束。应保留作为调度机制与实验维度，而不是用它替代AMX数据流与online状态问题。

## 11. 本轮继续推导的补充方向

本节是基于前述问题继续提出的候选，不代表仓库已有实现，也不自动代表新颖性成立。

### 11.1 补充A：利用加性GAT结构减少逐边指数计算

Vanilla GAT分数：

$$s_{ij}=\operatorname{LeakyReLU}(L_i+R_j).$$

对某条边，令 $\beta=1$ 或负半轴斜率 $\lambda$，则：

$$e^{s_{ij}-c}=e^{\beta L_i}\,e^{\beta R_j}\,e^{-c}.$$

**机会。** 每个节点每个head的R会被多个邻居复用；可以为 $\beta\in\{1,\lambda\}$ 预处理两套源节点指数表示，将每条边的昂贵exp转为符号分支、gather、乘法和指数调整。目的节点也有对应两套因子。

**不能直接做的事情。** 存 $e^{R_j}$ 和 $e^{\lambda R_j}$ 可能溢出；全局大偏移不能靠最后相除自动恢复。

### 11.2 一个范围更可控的尾数—指数表示

令：

$$k_R^{(\beta)}=\left\lfloor\frac{\beta R}{\ln2}\right\rfloor,\quad
m_R^{(\beta)}=e^{\beta R-k_R^{(\beta)}\ln2},$$

L同理。参考c拆为 $c=k_c\ln2+r_c$，则：

$$
p_{ij}=m_L^{(\beta)}m_R^{(\beta)}e^{-r_c}\,
2^{k_L^{(\beta)}+k_R^{(\beta)}-k_c}.
$$

边的正负分支仍由 $L_i+R_j$ 决定，不能仅根据R的符号选择。连续分数仍然保留，不是把权重变成纯二次幂。

**[本轮实测]** 对8head、513条边的中等范围FP64合成L/R，分解权重与直接稳定exp的最大绝对误差为 $2.77555756\times10^{-15}$。[E03]

**未解决事项。** FP32先加后Leaky的舍入与分别指数分解不逐位等价；超大指数整型范围、尾数精度、FTZ、近零符号边界均需验证。当前只验证了中等范围的FP64代数，没有测缓存或AMX速度。

### 11.3 该分解什么时候可能有利

若平均每个节点被许多边复用，从约EK次指数计算转向按节点的数套NK预处理，可能减少AVX侧指数压力。但要新增尾数/指数缓存；使用FP32尾数和32位指数时，两个源分支约需要每节点每head16字节，另有目的端和原始L/R等状态，具体是否保留可优化。

低度图可能完全不划算：预处理与额外gather超过省掉的exp。缓存必须按层输入版本失效，不能跨不同X复用。

**验收。** 分开测预处理、边gather与计算、缓存命中、端到端；比较高质量向量exp基线。不要因为exp调用数变少就宣称更快。

### 11.4 全部边落在同一Leaky分支时的简化

若某行所有 $L_i+R_j\ge0$，则softmax中公共L取消：

$$\alpha_{ij}=\operatorname{softmax}_j(R_j).$$

若全部落在负半轴，则为 $\operatorname{softmax}_j(\lambda R_j)$。混合正负分支时不能如此取消。

预扫描邻域R的最小/最大可识别这种情况；若本来就做最大值预扫描，额外维护最小值成本可能较小。但这又增加条件路径，是否值得必须测量。不能以原GAT的“静态注意力排序”性质推导所有行权重都与目的节点无关。[R02]

### 11.5 补充B：给value附加常数1，顺带计算分母

在同一P下：

$$P[X,\mathbf1]=[PX,P\mathbf1].$$

可以让AMX输出最后一列作为量化权重对应的分母，减少分母与分子权重不一致问题，并可能减少独立标量求和。

**问题。** D恰好填满结果列时，多1列可能需要额外结果tile；右操作数需合成常数列；分母只能对每个邻居块计算一次，而不是每个特征块重复。若分母长期驻留TMM，后续控制路径不能错误读取陈旧副本。

这不是“免费加一列”。建议作为单独微基准：比较额外tile和load是否低于AVX分母计算成本。常量value测试仍要考虑归约顺序差异。

### 11.6 补充C：将归一化、转置、BF16转换合成单个消费者接口

从局部FP32 U到后续GeMM输入时，统一处理：

$$U\rightarrow U/\ell\rightarrow\text{可选高低拆分}\rightarrow\text{BF16/VNNI打包}.$$

避免四个独立pass反复访问同一数据。对于需要head/node转置的布局，可以在该过程完成目标地址计算。

**代价。** kernel更复杂，转置可能降低连续向量化；应先保留多个简单pass正确版本作对照，再融合。任何软件优化都不能跳过U量化反例的验证。

### 11.7 补充D：有误差界的早期丢弃，而不是因子小就清零

若某旧段的归一化权重质量为 $\mu_{old}$，且已知其value分量绝对值上界 $B_{old}$，则其贡献绝对值可由 $\mu_{old}B_{old}$ 约束。只有该界低于明确的误差预算，才有依据丢弃旧段。

仅看到 $e^{c_{old}-c_{new}}$ 很小并不充分，因为旧C可能很大；第9.3节反例已说明这一点。若继续经过W，还需要乘入相应线性算子的误差放大界或直接在输出空间建立界。

**状态。** 尚无生产实现；不建议第一版启用近似丢弃。先完成精确或精度受控的路径，再考虑这一可选近似。

### 11.8 补充E：把全层最大特征界变成可复用安全信息

对输入X计算每层或每特征块的 $B_X=\max|X|$，可辅助窗口安全检查和旧段贡献界。如果输入本来要转换为BF16，可在同一pass维护该统计，避免额外遍历。

但全局最大值可能非常保守，导致很多无必要回退；逐行邻域精确界又增加访问。应比较全层、分块和按需局部界。它是数值保护辅助，不是性能结论。

## 12. 多核、缓存、NUMA、指令生命周期与工程边界

### 12.1 AMX权限、配置与线程状态是不同层次

Linux官方文档说明，扩展状态使用权限的请求作用于进程，并描述了fork/exec与首次使用的行为；不能笼统写成“必须每个线程分别申请一次，否则必然错误”。但实际tile配置、执行状态与上下文管理仍需要遵守线程执行规则。[R05]

**实现建议。** 启动时检测CPU/OS支持并请求所需扩展权限；每个worker明确初始化它要使用的配置；检查失败返回并回退。使用系统头文件提供的符号，不把原稿中的旧称谓或示例数字直接当作通用API。

原v3在worker内请求权限是其具体实现，不由此推导官方权限是线程私有。[C03]

### 12.2 库调用与TMM所有权

从自定义AMX聚合进入MKL或其他GeMM时，不应假设库保持当前tile状态。简单安全方案是在调用前完成局部结果提交，在返回后重新建立所需配置。

若希望免去配置/接口开销，需自行提供共享配置下的消费者GeMM，或者依据明确ABI/接口合同操作。不能通过“实际一次似乎没有被清掉”推断长期安全。

### 12.3 线程数和嵌套并行

当前融合路径在OpenMP worker内使用 `mkl_set_num_threads_local(1)` 并在结束时置回0，说明作者已经避免了直接的嵌套多线程GeMM问题。[C02]

**进一步改进。** 使用作用域恢复，保存并恢复调用前的线程局部设置，而不是假设0总是正确的外部状态；处理异常和提前退出。顶层投影可使用多线程MKL，但其线程数、亲和性与聚合worker设置必须在记录中说明。

### 12.4 NUMA、首次触页与线程私有工作集

局部buffer的“线程私有”不等于已经位于该线程本地NUMA节点。应明确分配、首次写入和执行绑核的对应关系，测量跨节点访问影响。

图分区会影响跨分区边比例与源特征复用；重复权重或源面板可能改善局部性，也增加容量。不同worker各保留128KiB面板时，总工作集按worker数增长，不可仅用单线程buffer大小推断缓存驻留。

**边界。** 本次没有在目标机器测得NUMA或内存带宽瓶颈；这些是实验必须控制的变量，不是已确认的唯一原因。

### 12.5 调度与确定性

现有 `schedule(dynamic,1)` 帮助处理不均衡面板，但会带来任务调度和不同访问顺序。未来超长行跨worker时，归约顺序也会变化。

应提供两个模式：固定顺序用于调试与可重复误差核验；性能模式允许受控调度，但报告运行波动与精度变化。不能用“GPU/CPU本来就不完全确定”解释任何数值差异。

### 12.6 权重、图预处理及缓存失效

可摊销对象：固定W的BF16/VNNI打包、$Wa$、静态CSR/度排序/面板索引。不可无条件摊销对象：依赖当前X的L/R、动态score相关排序、源投影内容。

缓存key应包含层、输入版本、权重版本、shape、dtype和布局。若同一图接受新输入特征，不能复用上次Z或R的值。图拓扑变化也必须使源并集与调度元数据失效。

### 12.7 内存安全和边界校验

对所有 `N*D`、`N*K*d`、`E*K` 等大小使用溢出检查，再分配。检查MKL整数接口允许的维度和leading dimension范围，不只检查E。

输入CSR验证应保留现有的行指针单调性与列索引合法性，再补充非有限特征、输出容量和参数维度。对不满足条件的输入明确失败，不允许静默截断维度或int转换。

### 12.8 前端和后端的重叠不能只靠理想图示

AVX侧负责gather、Leaky、exp、求和、转换，AMX侧负责矩阵乘。使用不同计算资源提供潜在重叠机会，但依赖关系、load/store资源和准备不足都会限制实际重叠。[R03]

第一版先写串行生产—消费的正确微核，分别测三个时间：纯预打包AMX、纯前端、完整融合。随后增加双缓冲，检查完整时间是否接近理想重叠上界，而不是直接用两个独立微基准的最小值作为结果。

## 13. 成本模型与执行路径选择

### 13.1 模型应解释实际慢在哪里，而不是替代测量

建议总成本拆分：

$$
T=T_{prepare}+T_{score}+T_{exp}+T_{gather/pack}+T_{matmul}
+T_{base\_spill}+T_{extra\_scale}+T_{convert}+T_{schedule}+T_{output}.
$$

若存在重叠，不能直接将重叠阶段相加。应提供串行上界、理想重叠下界和测得的关键路径；保持worker累计时间与wall time的统计含义分离。

### 13.2 决策特征

| 因素 | 影响的主要成本 |
|---|---|
| D/d | aggregate-first的稀疏算术放大 |
| head数K | 原始X跨头复用与AMX行利用率 |
| 度分布/分位数 | 短行padding、超长行拆分和调度 |
| 源节点并集密度 | 多目的节点矩阵映射的有效乘法比例 |
| 源投影重复率γ | 局部Z方案的额外投影 |
| 邻域与特征工作集 | gather缓存行为与NUMA压力 |
| 特征分块F、邻居块B | C基础搬运、P重用与寄存器容量 |
| score跨度与越界分布 | online重定标及安全回退 |
| 精度路径 | U转换、高低拆分GeMM及误差 |
| ISA与worker数 | 指令能力、并发资源和总局部容量 |

### 13.3 AF与TF的粗粒度分界

只看稀疏算术，AF需要处理约 $D/d$ 倍工作量。因此，若有效AF吞吐量相对于TF的提升不足以覆盖该比例，还需依靠节省的全局访问等成本来补足。

实际比较可写为：

$$
T_A-T_T\approx
\frac{2EKD}{P_A}-\frac{2EKd}{P_T}
+\Delta T_{prepare/pack/convert/spill}-\Delta T_{global\ traffic}.
$$

$P_A,P_T$ 必须来自匹配形状与数据访问的实测有效吞吐量，不是宣传峰值。对局部投影路径还要加入γ控制的重算项。

### 13.4 Useful work、executed work与算术强度

若一个稠密tile包含大量padding零，实际TMUL FLOPs高于算法有效边贡献。报告：

$$\eta_{useful}=\frac{\text{有效边乘加}}{\text{实际执行乘加}}.$$

Roofline可用执行工作量解释硬件使用，也可用有效工作量解释应用效率，但必须标注口径，不能用执行FLOPs得到高吞吐量后，再按有效FLOPs解释低计算成本。

算术强度的分母应包含字节单位与所选内存层级；仅用元素数比值不等于FLOPs/byte。

### 13.5 缩放优化的收益上界

若可完全消除的缩放占原总时间比例为p，其他部分不变，则：

$$S_{max}=\frac1{1-p}.$$

例如p=0.03，上界约1.031。这只是解释性算例，不是当前AMX占比。未来AMX加速矩阵乘后p可能增加，因此应在最终数据流上重测，而不能只沿用旧FP32 profiling。

### 13.6 选择器不应过早复杂化

先给每层选择固定路径和固定B/F/R，建立可解释分界。只有固定选择明显不能覆盖图内异质性时，再引入短行/长行分组或动态选择。

选择器的目标是超过强固定配置基线，而不是仅超过统一的最差配置。训练选择器或调阈值仅使用开发数据；测试集上只执行已冻结规则。

## 15. 代码改造顺序与建议接口

### 15.1 第一阶段：先修测试工具，再优化算法

建议单独提交：

```text
01_correctness_and_benchmark_contract
    修复NaN/Inf、尺寸、零分母、输入范围校验
    移出计时区间内compare/打印/参考复制
    统计编译开关真正删除热路径容器维护
    保留原始日志和旧程序，注明旧结果边界
```

验收是：负测试必失败，计时只覆盖声明的执行内容；不是性能变快才算修复成功。

### 15.2 第二阶段：形成独立状态模拟器

```text
02_softmax_state_reference
    standard_online
    exact_max_prescan
    resettable_window_reference
    segmented_merge_reference
    deferred_scale_block_simulator
```

统一输入与输出合同，支持head、feature分块、mask/空行策略。旧fixed-origin方案仅放入反例测试目录，不作为默认候选。

### 15.3 第三阶段：真实AMX微核，不先拼完整复杂流水线

```text
03_amx_microkernels
    bf16_pack_contract_test
    prepacked_dense_tile_test
    head_as_row_gather_pack_matmul
    fp32_rescale_spill_reload
    fp32_to_bf16_and_projection_interface
```

分别测纯计算与完整生产—消费。微核需覆盖当前三层的形状及尾部，不只测试16/32整倍数。

### 15.4 第四阶段：整层数据流与局部布局

```text
04_full_layer_paths
    transform_first_strong_control
    aggregate_first_head_as_row
    source_panel_projection_optional
    per_layer_fixed_dispatch
```

固定一种简单正确的邻居/特征循环，完成尺度版本协议与输出node顺序恢复。此时再加入窗口和合并提交，便于测得增量效果。

### 15.5 第五阶段：低风险增量优化

按独立开关增加：条件重定标、合并提交、缩放与已有buffer接口合并、归一化/转换/packing融合。每次只改变一个主要因素，保持可回退的强基线。

分段低维合并、双BF16补偿、源指数缓存等放在独立实验分支，不能在主路径没有净收益前全部叠加。

### 15.6 建议API数据结构

```cpp
// 设计示意，不是已接入工程的可编译完整实现。
struct KernelContract {
    int heads, input_dim, head_dim;
    bool has_bias, has_residual, concatenate_heads;
    EmptyRowPolicy empty_row;
    PrecisionPolicy precision;
};
struct SoftmaxReference {
    double anchor;
    int64_t binary_shift;       // 仅二进制方案使用
    uint64_t version;
};
struct AccumulatorBlock {
    NodeId node;
    int head_begin, head_count, feature_begin, feature_count;
    EdgeIndex consumed_until;
    SoftmaxReference stored_reference;
    Location location;         // TMM或线程局部buffer
    bool dirty;
};
struct AttentionBlock {
    EdgeIndex begin, end;
    SoftmaxReference reference;
    int pending_consumers;
    WeightFormat format;
};
```

实际多head各自参考不同，工程中应采用head数组或每head状态；示意结构不能误解成所有head共享一个anchor。

### 15.7 明确拆分四类接口

**模型接口。** 描述真实GAT语义、权重、激活与head组合。

**数值接口。** 描述分数、P、C、分母、投影输入的精度及允许回退。

**布局接口。** 描述CSR、P、X pack、U panel和W pack；每个接口有独立小矩阵对照。

**执行接口。** 描述线程、TMM所有权、配置、缓冲区生命周期和计时边界。

如果把四类合同混在一个巨大的forward函数里，很难判断错误来自数学、数据布局还是线程。

### 16.1 正确性矩阵

| 维度 | 必测情形 | 目的 |
|---|---|---|
| degree | 0、1、2、31、32、33、63、64、65、超长行 | 空行、尾块、跨块、分段 |

| 数据流 | 标准online | 精确最大值预扫描 | 条件窗口 | 分段合并 |
|---|---|---|---|---|
| TF | 必做 | 必做 | 可接入比较 | 视接口需要 |
| AF局部U | 必做 | 必做 | 主候选 | 独立候选 |

再按FP32与实际AMX-BF16分别测试。模型、图预处理和线程数相同，但精度不同的结果要明确标注，不能全部统称“等价加速”。

### 16.3 性能分层测量

**层A：纯算子。** 已打包矩阵的TMUL、重缩放、转换和小GeMM。

**层B：真实微块。** CSR索引、L/R、exp、动态gather、packing到聚合输出的完整过程。

**层C：完整层。** 包含该层必要准备、局部投影和激活；图静态元数据可另计。

**层D：完整模型。** 当前三层独立传递自己的结果，模型前向结束后再做验证，确保计时边界清晰。

只有层D结果支持“端到端推理加速”；纯TMUL结果只能支持微核吞吐量。

### 16.4 指标应覆盖成本与有效性

至少记录：wall time、吞吐量定义、峰值workspace、实际图边数、useful/executed work、gather/packing字节、基础C读写、额外rescale读写、逻辑越界数、物理提交数、被缩放head数、配置次数、重复投影率、回退比例。

硬件计数器事件名依实际CPU和工具验证，不预先编造通用事件名称。DRAM字节需来自适当硬件测量，不能用数组容量替代。

### 16.5 隔离性能污染

- 正式speed二进制关闭细粒度计时、统计容器、debug比较与日志。
- correctness与profiling分别运行；不将worker-sum与wall相加。
- 为每条路径提供相同输入，路径顺序随机化或采用配对测量，避免始终最后一个路径享受或承受固定缓存状态。
- 解释预热、首次分配、首次AMX使用、首次权重打包是否包含在冷启动结果中。
- 重复次数由运行稳定性和资源预算预先确定，报告分布或区间，不只取最佳一次。
- 需要比较峰值内存时，每个变体独立生命周期或独立进程，不能同时保留其他五种结果缓冲区后归因给当前路径。

### 16.6 精度验收不能事后只放宽阈值

在实验前固定FP32控制的误差准则、BF16候选的任务精度容许范围和不支持输入的回退策略。给出绝对/相对误差与任务指标，不以单个阈值掩盖相消问题。

对真实checkpoint使用固定开发/测试划分；模型权重、图处理和推理输出顺序全部冻结。若逐层选择不同精度，应在开发侧决定并原样评估。

### 16.7 核心贡献的消融矩阵

先分别打开：head-as-row、精确预扫描、窗口参考、合并提交、延迟缩放、转换融合、补偿U、源面板缓存。重点检查组合收益是否低于单项之和，识别重复优化同一开销的情况。

**决定性实验。** 在相同完整数据流上，仅切换标准online与新尺度机制，观察额外TMM流量和端到端变化。这才能支持“online机制带来硬件收益”。

### 16.8 三道验收门

**G1：正确性与接口门。** 反例、尾块、NaN负测试、分块状态、真实硬件精度均符合合同。

**G2：执行成本门。** 额外算术、packing、基础spill和控制成本全部被计入，局部优化产生可重复净收益。

**G3：论文证据门。** 在强基线、多层/多图/多形状上复现收益，解释适用范围和退化情况，相关工作差异具体。

未过G1不进入性能结论；未过G2不以事件下降代替加速；未过G3不写宽泛的首创和普遍优越性。

### 17.2 不能忽略差异，也不能夸大差异

SparAMX中的数值稀疏/压缩KV与本项目由图拓扑决定的稀疏边不同；DF-GNN的GPU调度不等同于AMX的tile类型与配置约束；整数尺度论文可能同时量化分数/权重，而本项目候选只限制参考尺度。

这些差异是需要分析的研究空间，但**不能仅凭“硬件不同”或“图不同”宣称全部创新**。应明确已有机制在哪个接口失效，本项目如何处理，新增代价是什么，以及实验是否证实。

### 17.3 可以争取、但尚未证成的贡献

**贡献候选一：多头共享邻域的AMX执行组织。** 将head作为合法共享归约轴的矩阵行，衔接后续按head的节点面板投影，解释D/d、寄存器、packing和布局成本。

**贡献候选二：完整分块状态下的数值受控online执行。** 不是再提出一个阈值，而是提供参考重置、独立head提交、尺度版本、必要搬运合并与精度接口的一致协议。

**贡献候选三：经验证的多路径选择。** 在TF、AF和局部源投影之间依据工作量与局部性选择，明确哪些层适合AMX聚合、哪些层不适合，避免用较弱基线制造统一加速。

这些仍是待验证主张。没有硬件结果前，不写“本文实现了显著加速”；没有充分查重前，不写“首次提出head-as-row”等过宽结论。

### 17.4 期刊扩展应如何与原TFS区分

首先如实说明原TFS的实际内核：静态图邻居访问、逐边特征投影展开、输出tile驻留。随后说明GAT新增了哪些原实现没有的问题：动态head权重、分母状态、参考尺度、L/R准备、跨头复用、额外精度接口。

不要仅把原方法图中A替换成alpha就当成扩展；也不要把新FP32局部U路径假装成原TMM内核的直接继承。

若期刊最终使用的是另一种执行顺序，允许承认它是对TFS目标的延伸，而不是逐条保留原执行顺序。正确的研究连续性是“减少无效中间访问并提高整体效率”，不是“永远坚持原来的某个循环”。

### 17.5 建议论文证据组织

1. 模型语义与四种执行顺序：明确真实计算量和中间数据。
2. AMX约束分析：形状、FP32/BF16接口、动态稀疏映射和配置生命周期。
3. 数据流与尺度协议：给出保持的不变量，说明新内容相对已有条件缩放的差异。
4. 精度与反例：展示错误方案为什么不成立，证明最终方案覆盖了哪些范围。
5. 实验：匹配强基线、模块消融、真实checkpoint、代际和形状适用范围。

这只是组织建议，不是已经可以填写结果数字的论文草稿。

### 18.3 哪些问题可以说“已解决”，哪些还不可以

**已经澄清的事实。** 原TFS真实计算顺序、当前原型非AMX、Vanilla GAT的线性重排条件、稀疏工作量差异和主要ISA约束。

**已经复现的漏洞。** 固定原点误差、U量化信号丢失、缩放因子提前下溢，以及旧NaN门禁负例。

**已通过有限软件测试的候选。** 可重置参考、分段合并、分母一致性、双BF16修复特定反例、源指数分解的中等范围FP64代数。

**尚未解决。** 完整AMX实现、尺度协议的流水化正确性、真实硬件数值行为、端到端净收益、真实checkpoint精度和最终创新性闭合。

### 18.4 停止条件针对具体候选，不是停止整个研究

- 某精度路径无法满足预先定义的模型误差要求，就停止把它作为默认路径，保留反例和成本记录。
- 若完整AMX AF在目标形状上仍无法覆盖D/d与packing成本，就改走TF或局部源投影；不能靠换弱基线挽救结论。
- 若新缩放机制不优于标准online或精确预扫描，就不把它写为主要加速贡献，仍可保留作为负结果。
- 若新增机制与已有工作仅概念相同、没有可验证的AMX特定差异，不作首次声明。

这些条件让研究收敛到证据支持的路径，而不是因为某个候选失败就否定整个GAT/AMX方向。

### 18.5 最小下一步

先完成三个可以独立验收的交付：**修复正确性与计时基准；实现分块尺度状态模拟器；实现一个包含动态packing、真实rescale和后续转换接口的AMX微核。** 三者完成后，再决定是否将online缩放提升为主要论文贡献。

下面是独立脚本，不依赖此前ZIP内的其他Python文件。保存为 `appendix_a_minimal.py`，在具有NumPy的环境中执行：


本轮已实际执行该脚本。它复现旧固定原点漏洞、普通FP32缩放因子提前下溢，以及额外U量化反例；同时演示有限输入上的可重置参考和双BF16修复候选。**`legacy_fixed_anchor` 故意保留已知错误，只用于反例，不应成为生产默认实现。**

脚本只接受有限、非空、无mask的FP32输入；真实GAT的空行和mask需由第8、16节的合同另行处理。它不是AMX指令仿真，也不证明任意输入的误差上界。

```python
#!/usr/bin/env python3
"""Software-only numerical audit. No AMX instructions or performance claims.
Run: python appendix_a_minimal.py
Requires Python 3.9+ and NumPy. Empty/masked neighborhoods are out of scope.
"""
from __future__ import annotations
import json
import platform
import numpy as np


def inputs(scores, values):
    s = np.asarray(scores, dtype=np.float32)
    v = np.asarray(values, dtype=np.float32)
    if s.ndim != 2 or v.ndim != 2 or s.shape[1] != v.shape[0]:
        raise ValueError("scores=[heads,edges], values=[edges,features]")
    if min(s.shape) == 0 or v.shape[1] == 0:
        raise ValueError("Nonempty heads, neighbors and features required")
    if not (np.isfinite(s).all() and np.isfinite(v).all()):
        raise ValueError("Only finite FP32 inputs supported")
    return s, v


def reference(scores, values):
    s, v = inputs(scores, values)
    s, v = s.astype(np.float64), v.astype(np.float64)
    p = np.exp(s - s.max(axis=1, keepdims=True))
    return (p @ v) / p.sum(axis=1, keepdims=True)


def bf16_rne(x):
    """FP32 -> BF16 RNE -> FP32 storage; NOT a full AMX emulator."""
    z = np.asarray(x, dtype=np.float32)
    if not np.isfinite(z).all():
        raise ValueError("Finite input required")
    u = z.view(np.uint32)
    b = (u + np.uint32(0x7fff) + ((u >> 16) & 1))
    y = (b & np.uint32(0xffff0000)).view(np.float32)
    if not np.isfinite(y).all():
        raise FloatingPointError("BF16 conversion overflow")
    return y


def ordinary_online(scores, values, block=32):
    s, v = inputs(scores, values)
    if block < 1:
        raise ValueError("block must be positive")
    h, n = s.shape
    c = np.zeros((h, v.shape[1]), np.float32)
    den = np.zeros(h, np.float32)
    m = np.full(h, -np.inf, np.float32)
    for j in range(0, n, block):
        sb = s[:, j:j + block]
        mn = np.maximum(m, sb.max(axis=1))
        with np.errstate(under="ignore"):
            r = np.exp(m - mn)
            p = np.exp(sb - mn[:, None])
        c = r[:, None] * c + p @ v[j:j + block]
        den = r * den + p.sum(axis=1)
        m = mn
    return c / den[:, None]


def legacy_fixed_anchor(scores, values, block=2, window_bits=4):
    """Intentionally retained BUGGY FP32 candidate, for counterexamples only."""
    s, v = inputs(scores, values)
    h, n = s.shape
    origin = s[:, :min(block, n)].max(axis=1)
    q = np.zeros(h, np.int64)
    running = np.full(h, -np.inf, np.float32)
    c = np.zeros((h, v.shape[1]), np.float32)
    den = np.zeros(h, np.float32)
    for j in range(0, n, block):
        x = (s[:, j:j + block] - origin[:, None]) * np.float32(np.log2(np.e))
        running = np.maximum(running, x.max(axis=1))
        trigger = running > q + window_bits
        if np.any(trigger):
            qn = q.copy()
            qn[trigger] = np.maximum(q[trigger], np.ceil(running[trigger]).astype(np.int64))
            with np.errstate(under="ignore"):
                c = np.ldexp(c, (q - qn)[:, None]).astype(np.float32)
                den = np.ldexp(den, q - qn).astype(np.float32)
            q = qn
        with np.errstate(under="ignore"):
            p = np.exp2(x - q[:, None].astype(np.float32)).astype(np.float32)
        c += p @ v[j:j + block]
        den += p.sum(axis=1)
    return c / den[:, None]


def reset_window(scores, values, block=32, window_bits=4):
    """Correctness candidate: resettable FP64 reference, stored FP32 state.
    No promise of arbitrary-input accuracy, hardware speed or AMX FTZ matching.
    """
    s, v = inputs(scores, values)
    if block < 1 or window_bits < 0:
        raise ValueError("Invalid block/window")
    s = s.astype(np.float64)
    h, n = s.shape
    ref = np.zeros(h, np.float64)
    c = np.zeros((h, v.shape[1]), np.float32)
    den = np.zeros(h, np.float32)
    events = 0
    for j in range(0, n, block):
        sb = s[:, j:j + block]
        mb = sb.max(axis=1)
        if j == 0:
            ref = mb.copy()
        else:
            change = mb - ref > window_bits * np.log(2.0)
            if np.any(change):
                rn = np.where(change, mb, ref)
                with np.errstate(under="ignore"):
                    factor = np.exp(ref - rn)
                # Multiply BEFORE rounding the factor/product to FP32.
                c = (c.astype(np.float64) * factor[:, None]).astype(np.float32)
                den = (den.astype(np.float64) * factor).astype(np.float32)
                ref = rn
                events += 1
        with np.errstate(under="ignore"):
            p = np.exp(sb - ref[:, None]).astype(np.float32)
        c += p @ v[j:j + block]
        den += p.sum(axis=1, dtype=np.float32)
        if not (np.isfinite(c).all() and np.isfinite(den).all()):
            raise FloatingPointError("Accumulator range exceeded; replay safer path")
    if not (den > 0).all():
        raise FloatingPointError("Invalid denominator")
    return c / den[:, None], events


def main():
    report = {"scope": "Software-only audit; no AMX or trained-model claims",
              "python": platform.python_version(), "numpy": np.__version__}
    v = np.array([[0.], [0.], [0.], [1.]], np.float32)
    rows = []
    for M in (1e5, 1e6, 1e7, 1e8, 1e9):
        s = np.array([[-M, -M, 0., 1.]], np.float32)
        truth = float(reference(s, v)[0, 0])
        bad = float(legacy_fixed_anchor(s, v)[0, 0])
        good, events = reset_window(s, v, block=2)
        rows.append({"M": M, "reference": truth, "legacy": bad,
                     "reset_candidate": float(good[0, 0]), "events": events})
        assert abs(float(good[0, 0]) - truth) < 1e-6
    assert abs(rows[3]["legacy"] - rows[3]["reference"]) > 0.2
    report["fixed_origin"] = rows
    s = np.array([[0., 120.]], np.float32)
    v = np.array([[1e38], [0.]], np.float32)
    good, _ = reset_window(s, v, block=1)
    report["factor_underflow"] = {
        "reference": float(reference(s, v)[0, 0]),
        "ordinary_fp32": float(ordinary_online(s, v, block=1)[0, 0]),
        "reset_candidate": float(good[0, 0])}
    A = np.array([[.5, .5]], np.float32)
    X = np.array([[1., 1.], [1.0078125, 1.]], np.float32)
    W = np.array([[1.], [-1.]], np.float32)
    U = A @ X
    hi = bf16_rne(U)
    lo = bf16_rne(U - hi)
    tf = float((A @ bf16_rne(X @ W))[0, 0])
    af = float((hi @ W)[0, 0])
    split = float((hi @ W + lo @ W)[0, 0])
    assert tf == .00390625 and af == 0. and split == .00390625
    report["U_rounding"] = {"transform_first": tf, "aggregate_first": af,
                            "two_part_candidate": split}
    try:
        inputs([[np.nan]], [[1.]])
    except ValueError:
        report["NaN_input_rejected"] = True
    else:
        raise AssertionError("NaN input was not rejected")
    print(json.dumps(report, indent=2, ensure_ascii=False))


if __name__ == "__main__":
    main()
```

```cpp
// Standalone validation/timing-boundary template; not a GAT or AMX benchmark.
// g++ -O2 -std=c++17 appendix_b_validation.cpp -o appendix_b_validation
#include <algorithm>
#include <chrono>
#include <cmath>
#include <iostream>
#include <limits>
#include <string>
#include <utility>
#include <vector>

struct CheckResult {
    bool passed = false;
    long double max_abs = 0;
    long double relative_l2 = 0;
    std::string reason;
};

CheckResult check_result(const std::vector<float>& actual,
                         const std::vector<float>& reference,
                         long double abs_tol,
                         long double rel_l2_tol) {
    CheckResult result;
    if (actual.empty() || actual.size() != reference.size()) {
        result.reason = "Empty output or size mismatch";
        return result;
    }
    if (!std::isfinite(abs_tol) || !std::isfinite(rel_l2_tol) ||
        abs_tol < 0 || rel_l2_tol < 0) {
        result.reason = "Invalid tolerance";
        return result;
    }
    long double error2 = 0, reference2 = 0;
    for (std::size_t i = 0; i < actual.size(); ++i) {
        if (!std::isfinite(actual[i]) || !std::isfinite(reference[i])) {
            result.reason = "Nonfinite element at index " + std::to_string(i);
            return result;
        }
        const long double x = actual[i], r = reference[i];
        const long double diff = x - r;
        result.max_abs = std::max(result.max_abs, std::abs(diff));
        error2 += diff * diff;
        reference2 += r * r;
    }
    if (!std::isfinite(error2) || !std::isfinite(reference2)) {
        result.reason = "Error reduction overflow";
        return result;
    }
    // The floor is part of this template's contract, not a universal metric rule.
    result.relative_l2 = std::sqrt(error2 / std::max(reference2, 1e-30L));
    result.passed = std::isfinite(result.relative_l2) &&
                    result.max_abs <= abs_tol &&
                    result.relative_l2 <= rel_l2_tol;
    result.reason = result.passed ? "PASS" : "Tolerance exceeded";
    return result;
}

struct TimedResult {
    double seconds;
    CheckResult check;
};

template <class Forward>
TimedResult time_forward_only(Forward&& forward,
                              const std::vector<float>& original_input,
                              const std::vector<float>& expected,
                              long double abs_tol,
                              long double rel_l2_tol) {
    // Input reset/copy is outside this example's declared timing boundary.
    auto input = original_input;
    const auto start = std::chrono::steady_clock::now();
    auto output = forward(input);
    const auto stop = std::chrono::steady_clock::now();
    // If forward launches asynchronous work, synchronize BEFORE 'stop'.
    // This CPU template assumes forward returns only after completion.
    const double seconds = std::chrono::duration<double>(stop - start).count();
    auto verdict = check_result(output, expected, abs_tol, rel_l2_tol);
    return {seconds, std::move(verdict)};
}

int main() {
    const float nan = std::numeric_limits<float>::quiet_NaN();
    if (!check_result({1.f}, {1.f}, 1e-6L, 1e-6L).passed) return 1;
    if (check_result({nan}, {1.f}, 1e-6L, 1e-6L).passed) return 2;
    if (check_result({1.f, 2.f}, {1.f}, 1e-6L, 1e-6L).passed) return 3;
    if (!check_result({0.f}, {0.f}, 1e-6L, 1e-6L).passed) return 4;
    auto result = time_forward_only(
        [](const std::vector<float>& x) { return x; },
        {1.f}, {1.f}, 1e-6L, 1e-6L);
    if (!result.check.passed) return 5;
    // Do not report this trivial call as a performance measurement.
    std::cout << "validation_and_timing_boundary_selftest=PASS\n";
}
```

### B.1 将模板接回当前基准时的注意事项

此例将输入复制放在计时外，输出分配由forward内部决定。真实实验应分别说明冷启动、稳态与workspace预分配的口径；不要只给新方法预分配而让基线每次分配。

完整模型的每条路径应返回自己的最终输出，再在计时结束后与独立oracle比较。逐层测试可以使用共同输入；端到端测试应让各路径传播自己的中间结果。这两种模式不能混淆。

### B.2 真正关闭热路径统计

仅让 `fine_now()` 返回空时间点还不够。应通过编译期策略同时移除：`push_back`、统计向量扩容、逐行ratio计算、critical内统计数组合并，以及只为profiling服务的分支。

可采用 `template<bool CollectStats>` 与 `if constexpr`，分别实例化 correctness/profile/speed 版本。speed版本仍保留必要的输入合同校验；不要为了速度删除会影响内存安全的边界处理。

### B.3 原始失败日志与新结果不能覆盖混写

修复门禁和计时后，为新运行使用新目录、源码哈希、编译命令与输出清单。旧结果保留并注明问题，不将旧数字静默替换成新数字，也不把同名日志混在一张表中。
