V1 Job10996305 observed a large Mycielskian sparse-stage speedup but used BF16 feature values drawn from small integer multiples of 1/1024; all reordered sums happened to match FP32 exactly. This v2 is an independent source/binary/run snapshot and leaves v1 unchanged. It addresses only that numerical gate weakness.

Keep the v1 graph set, 128-wide BF16 input, Identity TR16 plan, rowwise/fanout/shared computations, source-mask rules, duplicate rejection, 16 shared-node OpenMP threads, default NUMA policy (no interleave), one warmup and three measured repetitions, and timer boundaries. Change **only** feature generation: deterministic mixed 64-bit seed per `(node, feature)`, extract a 24-bit uniform mantissa into FP32 `[0,1)`, then truncate to BF16. This creates a broad exponent/mantissa distribution closer to the original nonnegative random H than v1's fixed-denominator small integers. It is still synthetic; real model input and two-layer propagation remain separate acceptance gates.

Reuse prior directed/overlap/empty/tile-boundary fixtures; deliberately reject duplicate-edge fixture. The same precomputed plan remains the controlled contrast between fanout and shared aggregation.

Run on one shared `intel` node, 16 CPUs, at most 32 GiB and 90 minutes, in a unique run directory. Preserve stdout/stderr, source/binary/protocol hashes, preflight/Slurm accounting, raw results, failures and all three handoff updates.
