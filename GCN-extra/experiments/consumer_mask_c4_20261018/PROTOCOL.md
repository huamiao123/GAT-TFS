# C4 consumer-mask structural gate (2026-10-18)

Question: In the original unit-weight 128→128→128 cohort, do 16-row destination tiles contain enough *distinct sources with exactly the same consumer mask* to justify a new AVX shared-aggregation kernel? This is a structural feasibility test, not a performance or accuracy claim. HAG-like subaggregate sharing is prior art; no novelty is claimed from the algebra alone.

Run the complete 17-graph inventory, fixed order, with original CSR bytes (including duplicate and unsorted occurrences). Compare native Identity and original degree-only ascending `std::sort` scheduling, TR=16, D=128. Do not use NUMA interleave. No graph mutation, inferred normalization, or new edge weights. Frozen original/canonical kernels are untouched.

For each destination tile, map each source to a 16-bit mask of consumers. A source repeated within one destination is excluded from grouping conservatively; all its occurrences remain in the baseline count. For each mask with n valid source vertices and k destination rows, an ideal shared intermediate reduces vector additions from nk to n−1+k, saving (n−1)(k−1) per feature when n≥2 and k≥2. Count no benefit for other masks. This is an upper bound under reordered FP32 summation; actual conversion, metadata, scattered delivery, source loading, and numerical error are not modeled. Existing FULL projection count stays fixed at one 16-row AMX tile per nonempty tile; no AMX instruction savings are claimed.

Report exact E, N, tile source visits, duplicate exclusions, source-mask occupancy, eligible groups/edges, saving/E, estimated simple plan payload, max tile size, preprocessing time, and order hash. `plan_naive_6byte_source_plus_4byte_group_bytes` is a simple payload estimate, not a proven information-theoretic lower bound or measured traffic. Correctness gate is an independent Python oracle on directed, unsorted, duplicated, empty-row, boundary, high-overlap, and no-overlap fixtures; the real scan verifies CSR bounds, file size, and edge coverage. Compare input SHA-256 to the existing 17-graph inventory for every case.

One shared `intel` node and one CPU for the structure gate. Structural runtime on a shared node is descriptive preprocessing cost, not a formal performance measurement. A new kernel is considered only if multiple real graphs show material saved additions after excluding duplicates and potential metadata costs. No per-graph policy tuning or benchmark claim follows from this scan.
