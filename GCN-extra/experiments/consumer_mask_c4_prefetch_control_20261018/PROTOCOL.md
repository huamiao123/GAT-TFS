# C4 same-job prefetch on/off register control (2026-10-18)

Purpose: prior Job10996710 compared same-mask sharing against a canonical-like eight-ZMM rowwise reducer that also issues four next-source prefetches per edge. The remaining question is whether that prefetch makes the rowwise control unnecessarily slow on some graphs. This isolated experiment adds an otherwise byte-identical **register-resident no-prefetch** rowwise method in the same process. It does not modify the common-mask or same-plan fanout computations.

Four methods: `rowwise_np` (eight `__m512` accumulators, no software prefetch), `rowwise_pf` (same plus four next-source cache-line prefetches), same-plan per-source fanout, and same-plan shared-mask aggregation. Check `rowwise_np` and `rowwise_pf` outputs exactly identical before timing; then compare fanout/shared to rowwise_np using relative L2 and normalized max <=1e-2 and log BF16 aggregate mismatches. Reuse fixed six graph cohort from Job10996710: Indochina-2004, Mycielskian19, Hollywood-2009, as-Skitter, Reddit, RoadNet-CA. Original unit-weight CSR input SHA-256 and stage-one plan counts must match. Fixed deterministic broad-mantissa BF16 input, D=128, Identity TR16. Duplicate edges are rejected by the mask plan.

One `intel_expr --exclusive` node, 32 physical cores on one socket or invalidate placement; default NUMA, no interleave. One warmup per method, eight measured rounds balanced across all four slot positions, including reversed orders. Output zeroing outside every timer. Save raw arrays, medians and the faster of the two register-rowwise medians per graph as a **conservative diagnostic reference**; this per-graph best-of-two is an oracle for evaluating opportunity, not a deployed policy. Same-plan fanout/shared remains the causal contrast for shared aggregation. Plan bytes/build time and all failures retained. Five prior smoke fixtures including rounding and duplicate rejection run before Slurm.

This remains only sparse BF16-input/FP32-output aggregation; AMX, activation, interlayer conversion and complete GCN precision/runtime are untested. Even a gain against both register controls cannot be reported as canonical FULL+AMX performance. Preserve preflight and compiler/source/binary hashes, CPU placement, exact commands, Slurm raw output/accounting and all three GCN-extra handoff ledgers. Paper eligibility false.
