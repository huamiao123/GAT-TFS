## Conclusion and correction

Paper Table 2 is generated by `gcn_e2e_v3.cpp` (FP32 intermediate + BF16 final), not the older `gcn_e2e_bench.cpp` (FP32 final with redundant global output zeroing). Its historical log `gcn_e2e_v3_all_4624352.log` matches all 17 eligible table entries, allowing for rounded seconds in the paper. The earlier 0.891x aggregate result refers to the older source version only; using it to conclude that the paper TFS is slower than MKL was incorrect. That inference is withdrawn. Old evidence is preserved.

The original v3 source also removes global output memset and changes output storage and loop organization. The version difference must not be attributed solely to BF16 output, NUMA, or the reduction extension. Current reduction candidates have not yet been compared against this paper v3 baseline.

## Numerical evidence and source discrepancies

Separate validator runs before raw timed executables on every graph. It checks the actual final BF16 output against the original FP32 MKL output over every element, reporting max_abs_error, mean_abs_error, relative_L2_error, and max_abs_error/max_abs_reference. Gate is 0.03 for both relative L2 and normalized max; this is numerical agreement, not classification accuracy. The raw performance executables are untouched.

17/17 full BF16-output checks pass. Maximum relative L2 0.013233; maximum normalized max 0.016462. See per-graph correctness.log and summary.csv.

The historical E2E precision function uses max_abs_error/max_abs_reference, while the manuscript presents a Frobenius relative error. The source precision block additionally reruns the final layer as FP32 output, although its timed final layer outputs BF16. Those historical checks therefore do not directly validate the timed final BF16 result. This run supplies that missing check separately.

The manuscript says median of five, but raw sources print BEST=min of five, and all eligible Table 2 values match the historical BEST entries. Both minimum and median are retained without silently relabeling either.
