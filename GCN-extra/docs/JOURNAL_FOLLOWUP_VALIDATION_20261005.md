## 固定条件与证据边界

父提交为 `33fb6b4270b94c1f38e8e9f3d94aed35595a384d`。原 TFS / 源 MKL 保持原代码；
新实验单独保存，旧 frozen snapshot 未覆盖。P1 复用已验证的 P0 内核，只修改 destination
调度。服务器只在 `wzh/GCN-extra` 写入，`yx` 只读。本轮最多同时使用两个单节点作业。

P1 在共享 intel 节点上采用 32 个物理核、单 socket、close/cores 绑定、默认 NUMA，
无 interleave；种子 12345、TR16/R64、D=F=128、原编译参数不变。数据为单位边权图、随机
H/W、两层 128→128→128 计算流；prepared E2E 包括 ReLU、层间转换，不包含图预处理和
初始 H/W 准备。没有分类模型 checkpoint，也不报告分类精度。

P1 每方法 warmup 后 5 次未插桩完整 forward；另有 5 轮正反顺序测量。
保留阶段计时、24 个采样子阶段、每线程统计、全部逻辑工作量和 3 次完整 forward PMU。
采样线程计时不能相加冒充 E2E wall time。共享节点数据用于当前机制判断，尚需独享复测。

## P1：投影预算不变的有限行分组

源码：[journal_grouping_p1_20261005](../experiments/journal_grouping_p1_20261005/)。
完整结果：[JOURNAL_P1_RESULTS_20261005.md](../results/journal-p1-20261005/JOURNAL_P1_RESULTS_20261005.md)。
冻结编译目录：`runs/journal-p1-build-20261005-111037`。
作业为 smoke 10869325、诊断 10869326、受控图 10869328、其余图 10869374；均成功。

在原 DegreeSort 每个位置保持 `q64=ceil(degree/64)` 不变，每个相同 q64 桶切成至多 4096
行的段，只在段内排序。source 分组使用每行前 64 个邻居的 source min-hash，page 分组
使用相对特征页编号 `source/16` 的 min-hash；后者不是实际物理页地址。固定 hash 和参数，
没有按逐图计时调参。行内 CSR 顺序、线程调度、内核、scatter 均不变；确定性 shuffle 为对照。

覆盖 17 张真实图 + 3 张受控图：880 次数值检查、480 次同投影范围逐位输出检查、
320 次插桩输出逐位检查、320 次逻辑工作量检查、60 次调度审计全部通过。
这些计数不含前置 3 张 smoke 图。每个位置 q64、FULL/B64 投影预算、邻居窗口和记录的状态
存取请求保持一致。指令数仍可能因分支、等待等变化；没有宣称所有实际机器指令不变。

为每个候选计入整个 pass 和分配，得到保守的候选成本估算；不是单候选预处理的直接计时，

### 机制证据与反例

3 张受控图的 N=524288、E=67108864、degree=128、每个 source 的全局入度=128，
source ID 映射一致。按实际 native DegreeSort 的 tile 顺序构造复用度 1/4/16，运行时 hash
与生成器 hash 相符。行内访问顺序未改；不同图不比较输出相等。

| tile 内构造复用度 | FULL Degree ms | FULL shuffle ms | Degree/shuffle |
|---|---:|---:|---:|
| 1 | 193.867 | 124.095 | 1.562 |
| 4 | 71.158 | 75.059 | 0.948 |
| 16 | 35.852 | 67.746 | 0.529 |

即使全局 source 频率相同，改变顺序的收益也会反转。真实图中 Myciel-source 的采样局部
复用 p50 从 2.065 提高到 2.653，时间却变差；page 提高到 2.731 并加速。这表明该采样复用
指标不能单独用作策略选择规则。访问距离、页分布、输出访问、并行等待等需要进一步区分。

720 个 PMU region 的事件采集、线程快照覆盖和 scaling 均成功，保留原始与每 TID 数据。
Reddit-source 的 generic cache misses 中位数比 DegreeSort 少约 31%；Myciel-page 少约 17%，
Myciel-source 反而增加约 7%。这些与对应性能方向相符，是访问行为改变的辅助证据。
generic cache event 没有细分 L1/L2/LLC/DRAM，不能据此证明具体 cache 或带宽原因；
初末线程快照也不保证覆盖瞬时线程。PMU 的测量区间与主时间样本分开。

当前判断：P1 在 Reddit/Myciel 等图上值得继续研究，尚不宜作为固定通用策略。
下一步应建立无需完整性能搜索的候选判据，并在保留图上验证选择与预处理成本。
当前没有训练/测试分离的自适应选择器，也没有把事后逐图最好候选当作方法。

## P2：相同工作量的 AVX / AMX 同核交错

源码：[avx_amx_overlap_p2_20261005](../experiments/avx_amx_overlap_p2_20261005/)。
结果：[P2_OVERLAP_RESULTS_20261005.md](../results/p2-overlap-20261005/P2_OVERLAP_RESULTS_20261005.md)。
作业 10869371、qhcn014、一个物理核；是局部交接微基准，不能冒充两层模型结果。

SERIAL 完成当前 tile 投影后准备下一 tile；INTERLEAVED 每个 AMX K-block 后准备下一 tile
的两行。两个版本均用同样的两个局部 buffer、source 顺序、FP32 归约、BF16 packing、
AMX 投影和输出存取。5 个完整 FP32 输出逐位检查和 10 个插桩检查通过。
每案例 32768 次 TDPBF16PS、1024×16 个 destination、8 MiB FP32 输出不变。

| 工作集 / 度 | SERIAL ms | INTERLEAVED ms | SERIAL / INTERLEAVED |
|---|---:|---:|---:|
| 256 KiB / 1 | 1.460 | 1.342 | 1.088 |
| 256 KiB / 8 | 1.941 | 1.920 | 1.011 |
| 256 KiB / 64 | 6.138 | 7.384 | 0.831 |
| 128 MiB / 64 | 36.573 | 36.970 | 0.989 |
| 128 MiB / 128 | 72.210 | 73.077 | 0.988 |

7 次交替顺序成对测量保留。度 1 的成对比值含低于 1 的样本，度 8 跨越 1，收益尚不稳定；
256 KiB / 度 64 的全部成对样本均退化，当前交错实现时间增加约 20.3%。
这版交错没有支持大规模稀疏 producer 的收益，不进入主内核；结论限于这一实现和形状。

旧 GNU objdump 2.30 无法识别 AMX 的 `(bad)`；失败的解码证据保留。改用 iced-x86 1.21.0
对真实 ELF 函数字节解码，零非法指令，二进制 hash 与服务器 manifest 相同。
已核实下一 tile 的 BF16 decode/FP32 add 出现在当前 tile 的 AMX 点积之间，参见
`assembly_audit.json` 与两个 `*_asm.txt`。静态反汇编计数不能当成动态指令数，
交错顺序和 PMU 也不能单独证明硬件有效重叠的因果机制。

## P3：延迟残差的硬件数值门槛

源码：[delayed_residual_gate_20261005](../experiments/delayed_residual_gate_20261005/)。
结果：[P3_RESIDUAL_GATE_20261005.md](../results/p3-residual-gate-20261005/P3_RESIDUAL_GATE_20261005.md)。
成功作业 10869364。先前 10869361 的启动路径失败、修复和日志一并保留。

输入为文档的抵消反例，缩放到 [-0.5,0.5]，H/W 可被 BF16 精确表示。在真实 AMX 上：

| 方法 | FP32 relative L2 | 既定 1e-3 门槛 | 投影份数 | TDPBF16PS |
|---|---:|---|---:|---:|
| 原 TFS | 0 | PASS | 4 | 128 |
| B2 ACCURATE | 0 | PASS | 4 | 128 |
| D1 单分量延迟修正 | 0.001956947 | **FAIL** | 3 | 96 |
| D2 双分量延迟修正 | 0 | 本反例 PASS | 4 | 128 |
| FULL ACCURATE | 0 | PASS | 2 | 64 |

D1 最终 BF16 输出仍和 reference 相同，因此只检查最后 BF16 会遗漏 FP32 数值问题。
整体反例实验 PASS 表示成功复现了 D1 拒绝，不能写成 D1 正确性通过。没有降低门槛，
也没有把 D1 纳入已接受 ACCURATE 的性能主表。

D2 只通过这一个反例，不能声称任意输入有精度保证；K=2 时也没有减少相对旧 ACCURATE
的投影量。一般 K 块下，旧法/D1/D2 为 2K/K+1/K+2 份投影，FULL ACCURATE 为 2 份。
若继续 D2，需先证明有限投影范围的必要性，再面对 FULL ACCURATE 这个强对照。
