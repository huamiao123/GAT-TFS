# TFS-Train v2 Mathematical Specification

Status: authoritative for v2, frozen 2026-08-04.

For an undirected graph, CSR stores only off-diagonal adjacency `A_off`. Let `s_i=(degree_off_i+1)^(-1/2)` and `Hs=diag(s)H`. Self loops are separate diagonal terms.

Forward is `T=(A_off+I)Hs` and `P=diag(s)TW+b`, exactly equivalent to `P=SHW+b` for `S=diag(s)(A_off+I)diag(s)`.

For upstream gradient `G`, define `grad_scaled=diag(s)G` and `ybar=(A_off^T+I)grad_scaled`. Then `dW=Hs^T ybar`, `dH=diag(s)(ybar W^T)`, and `db=sum_rows(G)`. These must be checked against direct textbook `S^T G`. `grad_scaled`, `ybar`, and final `dH` are distinct values.

All tensors use original node order. Degree sorting creates only a logical execution schedule. Dropout, activation and loss are outside this operator and are owned by PyTorch.
# TFS-Train v2 Kernel Layout

Status: authoritative design; C0 establishes interfaces, not optimized kernels.

- Pull-SpMM produces `ybar`, owner-computes, with no scatter, atomics, or resident CSC. Undirected CSR is physically reused but logs retain transpose semantics.
- `dH = ybar * pack(W^T)`, FP32 accumulation, followed by target `s` scaling.
- Preferred dW kernel computes `dW^T=ybar^T Hs`. AMX A is ordinary BF16 `ybar^T[16,32]`; B is VNNI-packed `Hs[32,16]`; C is FP32 `[16,16]`.
- Reduction blocks contain 32 nodes; tails are zero-filled. Forward/SpMM may retain 16-row scheduling, so both granularities coexist.
- Each thread owns aligned FP32 `dW^T`; reduction is deterministic thread -> core group -> NUMA -> global.
- Candidate two-level blocking: row panel in `{512,1024,2048}` and four dW accumulator tiles per tile panel. Compare against naive accumulator traffic and a DRAM-materialized strong baseline.
- `pack(W)` and mathematical `pack(W^T)` are independent. Packing is accounted end to end but is not the primary research risk.
# PyTorch Extension Specification

The active path is `PyTorch -> torch.autograd.Function -> C++ extension -> AVX-512 pull-SpMM -> AMX GeMM/dW`.

`TFSConvFunction.forward(x, weight, bias, a_off)` returns normalized GCN pre-activation and saves `x`, `weight`, `a_off`, `s`, and `Hs`. Backward returns `dH`, `dW`, `db`, and no graph gradient using the v2 equations.

PyTorch owns ReLU, dropout including the real mask and inverted scaling, cross entropy, optimizer, FP32 master weights, checkpoints, training loop and gradcheck. The extension must neither infer dropout masks from nonzeros nor replay RNG. C0 may execute the Python reference while a compiled C++ module proves ABI/import viability.
# TFS-Train v2 Experiment Specification

Every run reads and hashes server `AGENTS.md` and the research Skill, creates a unique immutable run directory, records versions/environment/affinity/Slurm identity/config/source hashes and raw JSON/CSV, and then updates all three handoff documents.

C0-v2 is one correctness/environment gate: FP64 and FP32 `P,dW,dH` alignment; internal/direct `Hs,ybar` equivalence; compiled extension import; one reference autograd pass; AMX, ABI, OpenMP, NUMA, binding, memory, hugepage and mmap audit; deprecated v1 paths absent from default build; B1 started; no P0/P1. It is not a performance result and cannot enter a paper table.

Formal performance later uses `intel_expr --exclusive`; correctness uses normal `intel`. Timing comparisons require identical precision, data, threads, affinity and boundaries.
