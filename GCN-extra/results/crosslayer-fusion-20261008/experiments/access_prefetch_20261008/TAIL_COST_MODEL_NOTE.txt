原 TFS 的固定 tile padding 工作量：短尾组边界说明
日期：2026-10-08
性质：只读源码核查与数学推导；没有运行新内核、修改排序、生成图或提交作业；不是性能实验结果。

讨论对象是固定 TR=B=16 的原始 TFS。对每个 destination tile，邻居位置循环运行 max_degree 次；每次执行固定大小的 AMX 运算。若只计这种重复投影，目标与各 tile 最大度之和成正比。该目标不包含访存局部性、线程负载均衡、输出位置、排序成本、缓存命中率或实际执行时间。

源码依据：original/gcn_e2e_v3.cpp
44—46 行：setup_tilecfg 将所有所用 tile 的 rows 固定设置为 TR=16，tail 没有重新配置较小行数。
72—77 行：make_degree_perm 按度全局升序排序。
91—101 行：batch 仅决定有效行数，max_deg 从这些有效行取最大值。
103 行：Hbuf 仍按完整 TR×128 清零。
105—142 行附近：每个 s<max_deg 执行 NP=2、KB=4、每 kb 四次 TDPBF16PS，即每个 max_degree 单位 32 次指令；输入不足的行依赖零填充。
STORE_FP32 / STORE_BF16：有效输出按 batch 写回，但计算 tile 仍固定 16 行。
af 游标逐个清除耗尽行，因此要求每个 tile 内的度非降序；不要求不同 tile 的最大度按全局升序排列。
当前原基准传入 R=64，是 TR 的整数倍，因此除全局尾部外没有额外的短 tile。

反例：N=17，度为 1,2,...,17。
直接全局升序得到 [1,...,16] 和 [17]，最大度之和是 16+17=33。
改成 [2,...,17] 和 [1]，每个 tile 内仍升序，最大度之和是 17+1=18。
所以在该固定 padding 模型中，投影指令数每层从 32×33=1056 变成 32×18=576，减少 45.45%。这里只是指令工作量推导，没有测量时间，不能写成 1.833 倍的实测加速。
上述 1,...,17 序列是组合模型的数值例子，可以由允许一般 CSR 重复项的输入实现；不能直接声明为 17 节点简单无自环图的度序列，后者最大度上限只有 16。
还有一个无需重复边、自环或孤立节点的可实现反例：构造 16 节点完全图 K16，再增加第 17 个叶节点，并将它连接到 K16 中任意一个节点。升序度为 [1,十五个15,16]。直接升序的满 tile 最大度为 15、单行 tail 最大度为 16，和为 31；将十五个15与16放进满 tile，把度1的叶节点留在 tail，和为 17。所有 tile 内部仍升序。该图只是说明反例符合简单无向图语义，没有生成其 CSR 或运行实验。

一般定理（固定 tile 数、固定一个短尾、所有组都按完整 B 行执行）：
将非负度排序为 x_1<=...<=x_N。设 N=qB+r，其中 0<r<B。
有 q 个 B 行满组和一个 r 行短组。所有合法分组中，最大度之和的最小值为
  x_r + x_(r+B) + ... + x_(r+qB) = x_r + x_(r+B) + ... + x_N。
构造：短尾保存最低的 r 行；剩余 qB 行按升序每 B 行分组。代码要求短组位于最后时，可把这些满组先顺次执行，再执行最低 r 行的短尾，保持每个组内部升序。
证明：将任意分组的组最大度排序为 m_1<=...<=m_(q+1)。最大度更高的最后 q+1-j 个组至多容纳 (q+1-j)B 行，所以前 j 个组至少容纳 N-(q+1-j)B=r+(j-1)B 行。这些行的度都不超过 m_j，因此 m_j>=x_(r+(j-1)B)。逐项相加得到下界，上述构造逐项达到。
当 r=0 时，直接升序每 B 行分组即达到相应下界 x_B+x_(2B)+...+x_N。r>0 时，直接升序后把最高度的最后 r 行留在短尾，也可能因度值并列而恰好最优，但不能无条件声称全局最优。

边界与使用方式：
1. 这是固定 padding 工作量目标的边界，不等于否定原论文排序方法的整体价值；引用论文时应先核实其定理是否明确假设 N 整除 B、是否对短尾另有处理，以及理论目标是否与实际 padding 一致。
2. 若 tail 改用更小 tile 行数、标量/AVX 路径或不同成本，目标需重新建模，不能直接套用此定理。
3. 所谓最优仅针对所有合法行分组；若还约束来源局部性、预设 bucket、固定 tile 成员、节点顺序或任务调度，则可行域不同。
4. 该排列可以保留每行 CSR 加法顺序，但在多线程系统中会改变任务和访存顺序，因此仍需独立数值及性能验证。
5. 本轮 access-prefetch 数据流使用 FULL 归约、每个非空 tile 一次投影，原 TFS 中随最大度重复投影的成本已消失。不能把该推导归因于 PF8，不能把它混入已冻结本轮候选或结果。
6. 没有改动 frozen original、任何旧论文对齐文档、现有 grouping/plan/kernel，也没有以该模型决定本轮运行的排序。
