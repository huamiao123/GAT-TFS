# 独立 Vanilla GAT baseline suite 实现与初测

## 实现范围

依据 `IMPLEMENTATION_CONTRACT.md` 新建独立 `baseline/`，没有修改旧 `implementation/` 数学路径。

| 路径 | 定义 |
| --- | --- |
| R0 `ref_fp32` | FP32 SGEMM → Z/L/R → 显式 score/p/alpha → stable softmax 聚合；仅正确性参考 |
| B0 `standard_bf16` | 全 head 一次 oneMKL BF16 GEMM → FP32 Z → AVX L/R → exact-max prescan → 多线程 AVX score/exp/weighted Z；性能主基线，无 TFS |
| B0-FP32 `standard_fp32` | 相同优化 sparse/attention，但投影使用 SGEMM；辅助性能结果 |
| B1 `tfs_bf16` | master W/a 静态 bL/bR → BF16 LR GEMM → exact-max prescan → 每边 pX 转 BF16 → W AMX；Degree Sort、16 destination rows、输出 TMM 驻留 |
| `matched_attention` | B1 attention 前端 + B0 后端，仅诊断，不作为新的主基线 |

B1 源码真实继承原 `amx_tfs_v3.cpp` 的 degree 升序逻辑排列、dynamic R-panel、TR=16、失活行 smart zeroing、下一邻居预取和原节点位置 scatter。每个 head 独立，每线程 AMX permission/configuration；所有 head 输出块在 TMM 保持到整组邻居扫描结束。d=40 pad 到48，D尾部 pad到32倍数。没有完整 Z/U/p/alpha，也没有 local-U + SGEMM。支持 d<=64、heads<=8，当前模型为 Din→8x32→8x32→1xC。

与旧 aggregate-first 原型的不同：该 B1 逐边执行 `(pX)W`，主要矩阵工作量约 O(EKDd)，会重复 source projection；不能用旧原型仅 D/d=8 的 sparse aggregation 膨胀来完整描述这一版成本。

## 正确性与 AMX 证据

编译链 icpx 2024.1.0，oneMKL 2023.0 Update2（模块名2023.2.0）。三次构建都通过。64 组 D/K/d 组合、degree 0/1/2/15/16/17/31/32/33/63/64/65/129、空行、partial tile/tail、extreme/equal/late-peak/common-offset score、NaN/Inf、CSR/参数尺寸/溢出测试均通过。R0 对独立 FP64 scalar oracle 和 NumPy 三层逐中间量 oracle 通过；AMX weighted-edge 运算对 BF16 scalar emulation 通过。完整任务精度验收尚未完成。

源码生成的汇编含 tileloadd/tdpbf16ps。`arxiv-10808269/vendor_amx_perf.txt` 中仅运行 B0 的进程记录 **27,571,749,888 amx_ops_retired.bf16:u**；该进程没有调用自定义 TFS 函数。结合 MKL_VERBOSE 和 CPU/库版本，确认本机 oneMKL projection 实际使用 AMX。

arxiv 的同输入逐层与路径自身三层传递都进行了比较。三层相对 R0：

| 路径 | max abs | relative L2 |
| --- | ---: | ---: |
| optimized FP32 B0 | 1.6093254e-6 | 3.3218977e-7 |
| BF16 B0 | 0.003334865 | 0.003105357 |
| BF16 TFS B1 | 0.003769811 | 0.003176968 |
| matched attention control | 0.003292255 | 0.003104528 |

这是显式 seed11 的随机参数，不是训练 checkpoint。BF16 误差合同需要开发集/真实 checkpoint 校准，日志明确标注 `accuracy_gate=UNCONFIGURED_NOT_ACCEPTED`。没有沿用旧固定 FP32 门槛判定 BF16 任务正确性。`scripts/evaluate_task.py` 已提供输出/labels/split/accuracy-drop 接口，等待真实权重和任务验收。任何当前数值都不能代表训练模型 accuracy。

## 测量条件与完整模型

主结果：Slurm **10808269**，`intel` 共享节点 **qhcn059**，16物理核，socket1，CPU44–59，OMP/MKL=16，close/cores，默认 first-touch，32GB内存配额，elapsed1:37，COMPLETED0:0。图为原有 arxiv.gatbin：N=169343、E=2484941、D_in=128、C=40；预处理是 undirected、deduplicated、每节点一个 self-loop，suite不再次修改图。

每条路径单独进程，2次 warmup，7次测量。三层各自传递自己的输出。下表是三层 forward：包含每层转换/attention/聚合/normalization/activation；图加载、static W/B 准备、Degree Sort、workspace 分配另报；所有 compare、finite scan、print 均在完整模型 timer 之后。profiling 与 speed 二进制分开。

| 路径 | 模型 median / ms | P95 / ms | 相对 BF16 B0 的速度比 |
| --- | ---: | ---: | ---: |
| B0 BF16 | 168.691 | 179.383 | 1.000× |
| B1 TFS BF16 | 586.236 | 594.112 | **0.288×（约慢3.48倍）** |
| B0 FP32 辅助 | 102.116 | 102.285 | 1.652× |
| matched attention control | 164.599 | 170.265 | 1.025× |

BF16 API/AMX 执行已经确认，但本轮 BF16 整体实现比 FP32 B0 更慢。阶段数据也显示 normalization/activation 等后续阶段时间有差异；当前只有共享节点数据，不能在缺少 CPU frequency/硬件状态证据时将差异归因于某一种硬件机制。必须保留更快的 FP32 对照，不能默认 BF16 必然更快。

此前 `arxiv-10808152` 因 srun 未传 -c 实际只获得1核。日志正确记录1核，保留为单核诊断，已在问题文档登记。当前脚本显式传递 CPU 配额，运行前读取 affinity 并选择同一 socket 的物理核；少于2核时 fail。

## Fixed-p：隔离 attention 前端

R0 生成相同 p/ell/input/checkpoint fixture；读取时核对 CSR 和 W/a 身份。A0 为 BF16 projection + AVX weighted SpMM，A1 为 weighted TFS AMX；共同输入 conversion、L/R、score/max/exp、fixture生成均不在计时内，normalization计入。2 warmups、7 repeats、AB/BA交替：

| 层 | A0 Standard / ms | A1 TFS / ms | A0/A1 |
| --- | ---: | ---: | ---: |
| 128→8x32 | 58.150 | 167.450 | 0.347× |
| 256→8x32 | 57.744 | 311.922 | **0.185×** |
| 256→1x40 | 8.941 | 36.884 | 0.242× |

三个形状都未显示 TFS 的净收益。特别是第二层，固定相同 attention 后仍约慢5.40倍，差异已经存在于数据流/实现后端，不能通过切换 softmax 基线将其归因于 attention 前端。

## 第二层 speed-build 细分 wall time

以下为每字段各自的7次中位数，因此不能要求字段中位数精确相加等于 total 中位数。

| 环节 / ms | B0 BF16 | B1 TFS BF16 |
| --- | ---: | ---: |
| input conversion | 7.339 | 7.292 |
| dense projection | 9.070 | 0 |
| L/R | 6.257 | 2.169 |
| max prescan | 0.819 | 0.835 |
| score/exp/aggregation 或 TFS 主核 | **36.179** | **313.816** |
| normalization | 9.058 | 8.950 |
| ELU | 10.797 | 11.210 |
| layer total | **81.577** | **344.831** |

最可靠的定位是：B1 第二层主核占 layer 大部分时间。节省完整 Z 投影和更快的 LR，未抵消逐边加权特征转换/AMX projection/动态 gather 的总成本。固定 p 结果支持这一判断。

代表性 frontend microbenchmark：B0 L/R AVX 在 L1/L2/L3 为5.382/6.333/0.107ms，静态 workspace SGEMM 为12.103/10.771/0.166ms，故固定 AVX。B1 LR BF16 GEMM 在三层为1.335/1.882/1.114ms，FP32 SGEMM为4.013/5.747/3.945ms，AVX contraction为4.339/8.372/3.375ms，故本阶段默认BF16 LR；没有按不同测试图临时挑选。

## Profile 子环节与解释限制

第二层 profile 两次 worker 累积时间平均值：

| 子环节 | worker 累积 ms |
| --- | ---: |
| TFS score/exp/denominator | 385.535 |
| gather + pX/RNE 父项 | 28901.773 |
| 其中 gather load | 6624.420 |
| 其中 expand/mul/RNE/store | 7083.826 |
| tile load | 1204.177 |
| TDPBF16PS compute | 874.315 |
| scheduling/zeroing/prefetch | 656.553 |
| tile store / output scatter | 3.668 / 72.493 |
| B0 score/exp/denominator | 356.922 |
| B0 weighted Z load/FMA | 533.193 |

**这些不是无干扰的真实占比。** Profile对每个16元素向量和tile操作读时钟，TFS该层 wall升到3749ms，speed-build只有345ms；gather父项包含内层读时钟的巨大额外成本，且各子项计时调用频率不同。父子项不能相加，worker时间不能当成wall，不能用上述比值直接声称转换是compute的若干倍。细分字段可用于后续受控微基准/采样设计；当前瓶颈结论优先依据speed-build主核wall和fixed-p。

该层逻辑 AMX neighbor steps（含head）=1,319,080；executed FMA=172,894,453,760；额外 row/feature/output padding FLOPs=20,082,720,768。这些计数在speed构建由静态调度推导、timer结束后记录，运行中没有重型Stats。

## 当前验收状态

实现、编译、独立 oracle、边界/negative tests、AMX运行证据、fixed-p/full-layer/full-model测量接口均已完成并运行。完整任务准确率门槛和正式性能验收仍未完成：需要真实 checkpoint、开发集阈值，以及固定硬件环境的正式多次测量。当前共享节点随机参数结果只用于研究诊断，未开始新融合方法“ours”。
